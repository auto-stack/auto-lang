## 0. 调研结论（2026-08-23 已核实，Phase 1 的输入）

chart 组件现状 = **只有 vue 端可用，且无正式声明**，具体三层问题：

1. **registry spec 是空壳**：AreaChart/BarChart/LineChart/DonutChart/Chart/ChartTooltip/ChartLegend 已注册（`ui_gen/widget/registry.rs:3197-3290`，Data 类），但每个 spec 的 `props`/`events` 都是**空 HashMap**——`data/categories/index/type/curve-type/category/colors` 等属性从未被声明为契约，目前靠生成器透传碰巧工作。
2. **vue 端靠生成器硬编码**：真实的 prop 发射逻辑散落在 `ui_gen/vue.rs` 的 match 臂（`area_chart` 等特判，:10836 起）、`emit_chart_prop`（:7646）、CurveType 枚举映射（:7669）、chart config（:10536）——**实现与声明分离**，是 Plan 435 审计出的"实现比声明多"的典型样本。vue 组件本体是 shadcn-vue（unovis 底座）`@/components/ui/chart-*`（auto-man vue.rs:127-131 管依赖）。
3. **vm/iced 与 a2r 双空白**：`ui/render_support.rs:208` 对 `chart|canvas` 显式 fallback（"chart/canvas not implemented"）；`ui_gen/rust.rs` 零 chart 处理（rust 生成模式静默无声）。
4. **Auto 组件的能力边界**（435 体系落地后核实）：官方 Auto 实现组件 = 现有 view 原语的组合（widgets-gallery `components/toggle.at` 等先例）。这套边界装得下 Toggle，装不下 chart——任意角度线段/路径/圆弧在 col/row/text/image 原语中无一可表达。
5. **生态调研（2026-08-24）**：
   - 本仓 **iced 0.14.0 的 `canvas` feature 已启用**（Cargo.toml:132）——iced 自带 canvas Program，提供 Path（line/bezier/arc/circle/rectangle）/Stroke/Fill/fill_text 原语，**引擎侧无需自研栅格化**，抗锯齿与曲线由 iced 自理。
   - iced 生态现成 chart 库：**plotters-iced 0.11.0 只支持 iced 0.13**，0.14 迁移 PR（joylei/plotters-iced#45）截至调研日未合并发布——采用即意味着 fork/git-pin 维护。
   - Rust "逻辑/绘制分离"派：**plotters**（DrawingBackend trait 架构正确但维护缓慢）、**Charton**（grammar-of-graphics、multi-backend，但 Polars-first 数据耦合重）、**lumen-charts**（宣称 renderer-agnostic 但 Vello/GPU 向，与本仓 RenderCommand 协议方向冲突）、**charts-rs**（SVG/PNG 一体化输出，非分离架构）、**egui_plot**（绑 egui）。共同问题：采用任何一个 = chart 逻辑进 Rust，与"chart 为 Auto 组件"的 435 路线冲突（vue=unovis、vm=Rust 库两套逻辑两套视觉）。
   - **结论：不引 chart 依赖**。几何层按 **d3-shape/d3-scale 的接口形状**用 Auto 写（line/area/arc generator + linear/band scale，v1 体量约 500–800 行），plotters 的 nice-ticks/曲线算法作移植参考。

**结论**（2026-08-24 定向）：**引擎给笔，Auto 持笔**——引擎只补一个 `canvas` 形状原语（基础组件，schema 声明）；chart 组件本体用 Auto 代码实现（几何逻辑全在 Auto，像素全走 canvas 原语）；vue 端先走第三方路线（unovis 组件已存在）。不做"引擎内置 Chart 控件"（那是 SVG 出现前的老路，会把可组合的逻辑锁进 Rust 并三端手工维护）。

**D. 几何语言能力 spike → 六缺陷修复（2026-08-24，charts-dev）**：为验证 chart 几何（d3-scale 风格）所需语言特性写 14 个测试（`vm/tests_chart_geometry.rs`），撞出并修复六个缺陷：
1. **EQ_F..GE_F（0xC7–0xCC）漏进 opcode VALID 白名单**——Plan 403-F 加操作码时枚举/engine/codegen 三处落地、白名单漏更，运行期恒 "Invalid opcode: 0xc7"（任何 float 比较）。

4. **Bina 混合算术无类型记录**——`var b = a * 1.0` 落 Unknown→按 Int 消费，f-string part tag 错标 Int（f32 位打印成 1084227584）；存储推断链补 Bina 臂（contains_float/double）。
5. **float 声明无存储强转**——只有 Double 臂；`var f float = <int>` 位模式直通（vmax==0.0 恒真的病灶）；补对称 Float 臂（Int→I32_TO_F32）。
6. **f32 算术盲 pop_f32**——ADD/SUB/MUL/DIV/NEG_F 对动态来源（Index/Dot/Call）的 int 操作数位重解释（int 80 → 1.12e-43）；改 tag 驱动操作数弹出（`pop_f32_operand`）。

**纪律（组件实现须遵守）**：float 中间量显式声明 `float`；int→float 经存储强转或与 float 字面量混合。
**已知未修（记录在案）**：int 实参传 float 形参无强转（规避：先 `var f float = <int>`）；f-string 直接内联混合算术的 tag 已由 ④ 修复覆盖。
