## 0. 调研结论（2026-08-23 已核实，Phase 1 的输入）

chart 组件现状 = **只有 vue 端可用，且无正式声明**，具体三层问题：

1. **registry spec 是空壳**：AreaChart/BarChart/LineChart/DonutChart/Chart/ChartTooltip/ChartLegend 已注册（`ui_gen/widget/registry.rs:3197-3290`，Data 类），但每个 spec 的 `props`/`events` 都是**空 HashMap**——`data/categories/index/type/curve-type/category/colors` 等属性从未被声明为契约，目前靠生成器透传碰巧工作。
2. **vue 端靠生成器硬编码**：真实的 prop 发射逻辑散落在 `ui_gen/vue.rs` 的 match 臂（`area_chart` 等特判，:10836 起）、`emit_chart_prop`（:7646）、CurveType 枚举映射（:7669）、chart config（:10536）——**实现与声明分离**，是 Plan 435 审计出的"实现比声明多"的典型样本。vue 组件本体是 shadcn-vue（unovis 底座）`@/components/ui/chart-*`（auto-man vue.rs:127-131 管依赖）。
3. **vm/iced 与 a2r 双空白**：`ui/render_support.rs:208` 对 `chart|canvas` 显式 fallback（"chart/canvas not implemented"）；`ui_gen/rust.rs` 零 chart 处理（rust 生成模式静默无声）。
4. **Auto 组件的能力边界**（435 体系落地后核实）：官方 Auto 实现组件 = 现有 view 原语的组合（widgets-gallery `components/toggle.at` 等先例）。这套边界装得下 Toggle，装不下 chart——任意角度线段/路径/圆弧在 col/row/text/image 原语中无一可表达。
5. **生态调研（2026-08-24）**：
   - 本仓 **iced 0.14.0 的 `canvas` feature 已启用**（Cargo.toml:132）——iced 自带 canvas Program，提供 Path（line/bezier/arc/circle/rectangle）/Stroke/Fill/fill_text 原语，**引擎侧无需自研栅格化**，抗锯齿与曲线由 iced 自理。
   - iced 生态现成 chart 库：**plotters-iced 0.11.0 只支持 iced 0.13**，0.14 迁移 PR（joylei/plotters-iced#45）截至调研日未合并发布——采用即意味着 fork/git-pin 维护。
   - Rust "逻辑/绘制分离"派：**plotters**（DrawingBackend trait 架构正确但维护缓慢）、**Charton**（grammar-of-graphics、multi-backend，但 Polars-first 数据耦合重）、**lumen-charts**（宣称 renderer-agnostic 但 Vello/GPU 向，与本仓 RenderCommand 协议方向冲突）、**charts-rs**（SVG/PNG 一体化输出，非分离架构）、**egui_plot**（绑 egui）。共同问题：采用任何一个 = chart 逻辑进 Rust，与"chart 为 Auto 组件"的 435 路线冲突（vue=unovis、vm=Rust 库两套逻辑两套视觉）。
   - **结论：不引 chart 依赖**。几何层按 **d3-shape/d3-scale 的接口形状**用 Auto 写（line/area/arc generator + linear/band scale，v1 体量约 500–800 行），plotters 的 nice-ticks/曲线算法作移植参考。

**结论**（2026-08-24 定向）：**引擎给笔，Auto 持笔**——引擎只补一个 `canvas` 形状原语（基础组件，schema 声明）；chart 组件本体用 Auto 代码实现（几何逻辑全在 Auto，像素全走 canvas 原语）；vue 端先走第三方路线（unovis 组件已存在）。不做"引擎内置 Chart 控件"（那是 SVG 出现前的老路，会把可组合的逻辑锁进 Rust 并三端手工维护）。

## 2. Phase 划分

### Phase 0 — 声明设计（轻，产出写回本计划）
- 与 [Plan 435](435-autoui-component-schema-unification.md) 对齐落点：统一声明体系已在 `plan-435-schema-unification` worktree 落地（基础组件 schema / 官方 Auto 实现 / 第三方统一注册，widgets-gallery 文档+demo 页）。chart 族按三路线注册：**canvas 原语 = 基础组件（schema）**；**chart 组件 = 官方 Auto 实现**（Phase 2）；**vue 端 unovis = 第三方**（Phase 1 过渡，长期可切同源路线）。依赖该分支合入 master 或 rebase 其上。
- **核实 vue SVG 直通**：生成器未知 tag 的 HTML 兜底（`force_native_elements`）能否直通 `<svg><polyline …>`——若可，vue 端 canvas 原语映射零引擎工作，Auto 实现的 chart 三端当天同源。
- 产出：每组件的 props 契约表（`data`: record 列表 / `categories`: string 列表 / `index` / `type: grouped|stacked` / `curve-type` / `colors` / `category`(donut) / `height|style`）、events 初版（仅声明 vue 可实现的）、**三端状态矩阵**（vue ✅ / vm ⏳ Phase 2 / a2r 随 canvas 原语）。
- 决策项：DSL 侧 chart 数据形状（list-of-record 的类型表达，牵涉类型系统对 record 字面量的支持）；Auto 几何计算的数值能力核对（float 运算/list 操作够不够刻度与坐标计算）。

### Phase 1 — vue 端正式化（第三方路线：声明 + unovis 渲染）
- chart 族按 435 体系的**第三方路线**注册：统一声明（Phase 0 契约表落库），渲染归既有 unovis/shadcn 组件，Auto 侧只做声明与数据绑定胶水。
- vue.rs 收敛：`area_chart/bar_chart/line_chart/donut_chart` 的 match 臂特判改为 spec 驱动发射（保留 CurveType 等值映射作为转换层）；`chart` 容器 config 路径核对。
- 契约测试（421 先例）：`tests/vue_capabilities.rs` 增 chart 用例——props 全组合、缺省透传、CurveType 映射、data 绑定表达式（`.model` 路径 vs 内联字面量）。
- **文档页**：`examples/widgets-gallery/` 增 **Charts 分组**（每组件一页：示例 + props 表，409/412 惯例）。顶级 `examples/charts-gallery/` 决策：并入 widgets-gallery 后退役（推荐），或保留为组合用法演示。
- 验收：charts-gallery 全部图在声明驱动路径下构建绿 + vue-tsc 绿；新契约测试全绿。

### Phase 2 — canvas 原语（引擎）+ chart 组件 Auto 实现（架构定向 2026-08-24）
分层原则：**引擎给笔（一个 canvas 原语），Auto 持笔（chart 组件本体）**。
- **引擎侧（最小）**：`canvas` 形状原语的 iced 实现**直接基于 `iced::widget::canvas` Program**（0.14，feature 已启用）——引擎只做「Auto 图元列表 → canvas Program」的桥接，Path/Stroke/Fill/文本与抗锯齿/贝塞尔/圆弧均由 iced 自理；`render_support.rs:208` 的 `"chart" | "canvas"` fallback 替换为真实现。RenderCommand 协议不动；386 golden 的 draw list 导出在桥接层挂钩。
  - **参考实现：[plotters-iced](https://github.com/joylei/plotters-iced)**——它解决的正是同构问题（外部绘图模型 → iced canvas 宿主），其 `ChartWidget` 对 canvas Program 的包装模式、`Renderer` 缓存策略、重绘触发与事件处理照搬经验。注意它基于 iced 0.13（我们 0.14），API 有差异：**参考其结构，不复制其代码，不引其依赖**（用户确认 2026-08-24）。
- **Auto 侧（主体）**：chart 组件用 Auto 代码实现（widgets-gallery `components/*.at` 模式）：model 持 data/categories/index，computed 做几何（min/max 归一化、刻度、系列→坐标），view 产出 canvas 图元 + text 轴标签。顺序：**LineChart 先行**（图元最少）→ bar/area → donut（圆弧，最后）。
- **vue 端 canvas 映射**：SVG 直通（Phase 0 核实结论落地）；Auto 实现成熟后 vue 端可从 unovis 第三方路线切到同源 SVG 路线，unovis 退役为可选。
- **a2r**：canvas 原语随 iced 路径生成（rust 模式同源可用），chart 组件三端矩阵更新真值。
- 验收：同一 `.at` 源 vue/vm 双端跑通，视觉无结构性差异（038 双后端惯例）。

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 435 分支合入时序 | Phase 0/1 的声明设计不依赖分支合入（先产出契约表）；实现类工作 rebase 其上 |
| vue SVG 直通不成立 | vue 端继续第三方 unovis 路线（Phase 1 本就独立交付），同源切换列为长期项 |
| Auto 几何数值能力不足（float/list 运算） | Phase 0 决策项核实（d3-shape 移植的最小集：min/max/四则/map/f-string）；缺口则最小补语言能力，几何骨架先行 |
| canvas 图元列表的 DSL 表达力（list-of-record 图元参数） | 图元形状设计尽量扁平（定长参数），Phase 0 与数据形状决策一并定 |
| donut 自绘几何复杂（圆弧 tessellation） | Phase 2 排最后，允许降级后续项 |
