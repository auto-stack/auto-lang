## F-781-R07（P2）：type_of消费参数未释放引用份额

位置：crates/auto-lang/src/vm/ffi/stdlib.rs:2789（shim_type_of）。影响T-25新增原语、AC-19集成及T-23/AC-18健康收口。分类：本次修复新引入的资源生命周期缺陷，不是对旧索引规则追加要求。

原语使用`task.ram.pop_nv()`取出参数，只读取tag并压入结果字符串，没有释放输入参数持有的堆/字符串池引用。正常VM参数装载通过rc_push/rc_push_slot保留一份引用；新结果覆盖被弹出的槽，后续任务清理已无法释放那份参数引用。相邻多态json原语采用`pop_arg_nv`和`StakeGuard::nv`配平所有权。

独立宿主type-of-lifetime.rs链接当前rlib，走生产源码编译及`call_fn_by_name_segment`，每组独立VM，调用结束后显式`rc_release_task_stack`和`reap_all`，排除延迟回收。每组循环100次：

| 输入与调用 | 调用结果 | 收尾前后活对象/字符串 |
|---|---|---|
| json.parse对象 → json.from_value对照 | Completed Ok | heap 0→0；pool 1→1 |
| 同形对象 → type_of | Completed Ok | **heap 0→100**；pool 1→1 |
| 每轮独立动态字符串 → json.from_value对照 | Completed Ok | heap 0→0；pool 2→2 |
| 同形动态字符串 → type_of | Completed Ok | heap 0→0；**pool 2→102** |

四组均正常返回，终态资源平衡断言失败，探针exit101。故类型结果正确不足以证明原语安全；长驻VM反复调用会累计无法回收的输入。该缺陷不依赖F-781-E02推测。

**修正要求**：按当前VM参数所有权约定消费输入，清除被消费槽并释放其引用份额；可参照同文件shim_json_from_value的pop_arg_nv/StakeGuard模式。补对象和动态字符串重复调用的终态平衡回归，并保留浮点零/整数零正确性。本review不修实现。

复现：先在原Plan树构建冻结CLI/rlib，再执行附件build-lifetime.ps1及生成的type-of-lifetime.exe。源码、构建参数、实际链接rlib路径和完整输出均在docs/plans/attachments/781/review-r7/，主仓原始证据不依赖工作树临时输出；生成exe可由脚本重建。
