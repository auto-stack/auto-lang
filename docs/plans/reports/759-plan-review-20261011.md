## Findings

### F-01 [P1] R7 把标签别名缺口误写成缺少组件声明（T-01 / AC-02、AC-05）

计划说 Plan 717 三道再生流程全未走，预期只新增 13 个 element 声明。但 `git show 5bad66e0f -- schema/aura.at` 明确包含五个 carousel 声明和 command 后端元数据修改；现态 `schema/aura.at:3759` 起已有 carousel 全族，`:3418` 已有 calendar，`:3820` 起已有 command 全族。生产代码 `ui/aura_view_builder.rs:2874-2990` 新接受 `Calendar` 和 kebab 写法，而 schema 使用 calendar / 下划线 canonical 名；这支持别名同步缺口，而不是十三个独立元素缺席。queue 围栏则确实缺 carousel 五项登记。

修订：分开记录 canonical 声明、accepted spellings/aliases、queue 登记、kitchen-sink 同步四面；再生后核对 aliases、props、tier、backends、sub_widgets 保留，禁止为每个拼写新增重复组件。新登记的 NotYet / NotConsumed 必须有真实理由，不能任意二选一以过门禁。再生 diff 与新增声明数量以实际结果为准。

同时撤回“全部测试侧、产品代码 diff=0”的笼统承诺：`aura/schema_loader.rs:838` 通过 `include_str!` 把 schema 编进产品，`ui_gen/widget/registry.rs:72` 消费它；`aura/element_coverage.rs` 是非 test-only 库源码。可以承诺保持既有用户语义，但必须显式列出生产元数据改动。验证应包含 schema loader / registry 的相关覆盖；建议带 `cargo tu` 验证生成消费端，如改到 VM/编译器生产实现则按 AGENTS 增补 `cargo tv`。

### F-02 [P1] UPDATE 命令可直接写到 auto-os 主检出（T-01 / AC-04）

`tests/docs_gen.rs:31` 经 `resolve_os_top_dir` 解析 gallery，`os_paths.rs` 按 env → 组内 auto-os → `D:/autostack/auto-os` 兜底。`docs_gen.rs:394-395` 的 UPDATE 直接 `fs::write` 已解析的路径。只建 lang-759/auto-lang 而不建 auto-os 兄弟时，执行计划命令会改另一仓主检出的应用源码，违反 worktree 隔离，也会干扰其他会话。

修订：需要写 auto-os 时先建立该仓独立 worktree，显式把 `AUTO_OS_ROOT` 指向它；再生前核验解析后的绝对路径确实位于该 worktree，记录两仓 base/commit/dirty 清单。只需构建 auto-term 时也应在其专用 worktree/独立 target 中进行，探针通过 env 定位 DLL，不能继续绑死主检出 target。UPDATE 测试写完会故意 panic，这属于生成信号，不能作为验收绿；随后清除 UPDATE env、重新编译再验证。auto-os 应使用本仓规定的构建/金样门禁；跨仓“配合提交”不能代替具体验证。

### F-03 [P1] 0 红、12 族实测绿和降级条款互相冲突（T-06～T-09 / AC-01、AC-02、AC-04）

草案允许 photo 后端缺席时 eprintln+return、DLL 缺席时 skip+return、plan502 保留 flake、跨仓用移交单替代落地，却同时承诺零红、12 族 scoped 绿和闭环清偿。Rust 测试中的普通 return 会被报告为通过，无法证明测试执行。两次 scoped 绿也不能证明并行 flake 已清偿。

修订：保留 photo stub 主方案，删除自动跳过备选。DLL 探针若应从日常档分离，显式定义可见的 ignored/集成选择规则，并为指定集成门禁强制检查 DLL、实际跑探针；缺 DLL 可记未执行，不能记 AC-02 pass。确认目标是全部清偿还是分阶段交付；若保留 T-08/跨仓未完成项，必须修改目标、验收和销账范围，不能仍以“cargo t 零红收口”完成归档。flake 应以有截止时间的任务完成状态驱动，保留原几何断言，不靠重试成功掩盖失败。

### F-04 [P2] 只锁直调 CALL 会丢失原缺实现错误覆盖（T-03 / AC-02）

PLAN-633 的 export 守卫与现有 fixture 确实解释 3142 不发射；调整该 fixture 合理。但当前建议只断言 exports/CALL，缺实现 RuntimeError 分支被列为可选。原测试的核心防线是 API 不应静默 no-op；只看字节码不足以锁真实调用结果，更不能覆盖缺实现契约。

修订：把“有实现直调且返回/副作用真实落账”和“无实现显式 RuntimeError”都作为必须覆盖。缺实现的发射形态与 native 3142 的错误语义应各有证据（可使用更低层 codegen fixture），不能仅直接调用 native 来声称发射链受覆盖。明确关闭/隔离 host bridge 状态，避免测试命中其他分支。

### F-05 [P2] 补泵的 deadline 覆盖不到 server.join（T-02 / AC-02）

补泵方向得到归档 748 T-00 与 `dynamic.rs:1556` 的证据支持；不过 `p748_spawn_server` 在 `listener.accept()` / Read 上阻塞无截止时间，计划在 `server.join()` 之后才创建 deadline。若发送链发生回归，测试会卡在 join，所谓“五秒未恢复”不能保护它。

修订：server accept/read/write 和等待结果都需有界，deadline 从启动/派发前覆盖完整流程，泵阶段仍验证精确 W:5/W:6；失败报告 parked/CPU/marker 状态。顺带处理 noawait 臂不应启动无请求服务器，以及 TempDir `mem::forget` 的测试资源泄漏，避免增加孤儿线程/文件。

### F-06 [P2] photo stub 缺少运行边界，壁纸备选放松了断言（T-05、T-06 / AC-02）

photo stub + string ID + 当前 URL 契约的方向正确。需要明确 `entries/dirs/root_missing`、条目 `id/title/date/size_str/width/height/sort_key/thumb_url/full_url` 等真实 schema，并断言请求被 stub 收到、HTTP continuation 完成后再读 View。仅包含 `api/photos/thumb` 的字符串检查不应代替预期 origin/app/id 的精确映射；OpenPhoto 的 full URL 应与所选 ID 一致。端口用 OS 分配，server 停止/join/请求超时有界；AUTO_HTTP_BASE 设置和恢复需隔离到测试子进程或所有使用者遵守的机制，单个局部 mutex 不能保护未参与锁的其他 libtest 用例。日常 nextest 一测一进程的隔离与裸 libtest 并行形态需要分别说明。

壁纸显式空 TempDir 的主案正确，目录需存活至测试结束，优先只改两测试的 config；不要泛改数十个调用共用的 helper 而不审核调用面。删除 `bg == expected || Path::is_file()` 宽松备选，它允许错误图片也通过，削弱 SetWallpaper / 背景注入断言。产品硬编码门控应另列范围和语义增量，不是消红的前置条件。
