# ACE里程碑与v0.6/v0.7版本边界

2026-10-24用户确认：提高v0.6的Rust版ACE语言引擎成熟度要求；先使其基本完善、能够复刻现有AutoVM/A2X的全部示例，再考虑Auto语言实现的ACE（AACE）。AACE实施延后到v0.7，不在v0.6提前迁移主体。本合同取代旧“v0.6 AAC自举”及“自举所需小子集满足后即可提前并行AAC/AAV”的排期。

## 1. 名称与版本

- **ACE**：统一编译执行架构/语言引擎，包括AC/AV/AJ、A2X及共同语义、产物、cache与生命周期服务；v0.6实现主体为Rust。
- **AACE**：Auto语言实现的ACE主体，列为v0.7目标；AAC（旧称ACC）和AAV是其中的组件实现/自举子线，不是v0.6的并行实现目标。具体主体/桥接清单、后端与代际合同在v0.7计划冻结；仅包装Rust引擎不算AACE。
- v0.6保持接口/格式可由Auto消费和未来实现的边界，不启动AACE主体迁移。Rust实现同时作为后续AACE对拍基准。v0.7实施仍先核v0.6成熟度门；仅版本日期到达或827完成不能自动解锁。

本合同明确v0.7主线方向，不提前创建完整v0.7任务表，不把全部远期候选装入该版，也不承诺完整AACE一次完成所有组件/平台。具体代际与主体范围由v0.7 Roadmap/Plan冻结。

## 2. 四个Rust版ACE里程碑

下列M1–M4均属于Rust版ACE，与工程拆分路线的同名M1/M2不同。

| 里程碑 | 成果 | 出口条件 |
|---|---|---|
| M1 核心框架成立 | 共享HIR/Typed MIR、ABC/AV、有限native/CTE、数据/所有权、cache与函数级增量/安装、真实源码基线 | 798/828、817/818及820–827各自按当前合同实际交付；827编号最后或单独完成不代表M1。原profile/AutoDown/精确失效/P95/内存与生命周期门均须成立 |
| M2 现有语言能力完整 | 决定保留的现有Auto语法、语义、类型、模块及必要语言运行时 | 原始源码端到端覆盖，不以parser接受、typed fixture或某后端有操作替代源码推导/lowering/执行；标准库与宿主需求按M3交叉推进，不能形成互等 |
| M3 混合生态可用 | Auto/C/Rust/Python接口、绑定与执行体系 | 按明确平台/类型/库/入口支持矩阵，真实验证导入/导出、所有权/释放、错误、回调/线程、依赖与部署/cache。基础FFI和必要宿主服务随M2提前，不等M2全完；不承诺任意库零适配 |
| M4 产品迁移与旧框架替换 | ACE承接现有AutoVM/A2X对应执行、转译及消费者路径 | 全示例兼容基线、必要宿主与产品入口验收完成后分入口切默认/收口；旧路径清理按可追溯退役合同实施，源码转译职责保留，并非全部改走ABC/AV |

四个里程碑是v0.6成熟度路线，不能全部塞入827或当前某个Plan。M2与M3交叉实施，M4可按已成熟入口持续验证迁移，最终收口不能抢在对应能力和兼容门之前。之后才进入v0.7 AACE实施；不再按“编译器源码只需小子集”跳过Rust版全示例成熟度门。

## 3. 全部示例的真实兼容基线

冻结现有AutoVM/A2X全部示例、语料及其目标后端/平台/feature、入口、真实依赖与资源，建立可审计分母和独立oracle。A2X按原有对应转译→目标工具链→实际运行验证，不要求所有示例都能走native或所有跨积组合，也不能减少既有支持矩阵。

逐例核输出/返回/错误阶段、副作用、交互、资源与退出；真实AutoUI/服务/FFI示例不能以首帧、仅import成功或内部模型替代。禁止删imports/分支、换MIR fixture、改expected或隐式回退旧引擎来补绿。缺工具/依赖、skip、未决语义均记录缺口；旧bug不自动变成新规范，确需废弃或破坏性变化单独明确裁定，不能因ACE不支持删分母。

G0–G8继续负责AV语言/产品逐项取证与切换，扩展到A2X的目标/示例矩阵需后续有界Plan认领。M1不是v0.6终点；全部成熟度目标未达时明确记录并由用户决定延期或版本调整，不静默降级成“骨架已成型即完成”。

## 4. 不变的工程边界

当前817/818、820–827及其他已批准Plan的任务、状态、进度、支持面和预算不被本合同直接改写；先沿现有排期、原D门及共享核心单写/交接完成，再按M2–M4的实际缺口拆适中Plan。现状只由Spec/代码与review/merge证据认领，不因路线提高目标而判绿。

增量/cache、热重载接缝、AutoDown、端到端代表编辑P95<1s与有界内存/磁盘贯穿Rust版扩面，不延期到AACE。全示例通过不证明完整AJ/优化JIT、OSR/deopt、自主codegen、任意活对象迁移或通用增量发布器完成；其实现按实际需求单列，不因本次版本调整自动加入旧框架兼容门。
