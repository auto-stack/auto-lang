## 2. 已核现状：两种解析路径，已有局部生产接入

- `experimental/ace/crates/core/src/source/parser.rs`、`lexer.rs`：手写源码前端，具有整模块入口及 `parse_function_fragment` 等增量片段入口，支持多个有限源码profile。
- `experimental/ace/crates/syntax-runtime`、`syntax-grammar`、`syntax-core`：配置驱动词法/无损CST/局部重扫及CST→同一AST的严格投影；现有语法资产为auto-core、auto-scalar、interface-mini-v1。
- `experimental/ace/crates/av/src/session.rs` 已实际调用 `incremental_reparse` 和 `project_decl_strict`，scalar常驻会话的暖编辑已消费通用CST。PLAN-787早期“只对照、不替换入口”不能概括PLAN-828后的全部现状。
- A2X store、native collections及闭包源码生产仍有手写函数/闭包片段解析路径。两路径并非两个互不相通的语言，已有共同AST和标量差分；也不能由标量对拍推定其全部profile覆盖、诊断、恢复和入口已经统一。

以上只是源码调查，不是本轮执行测试得到的新通过证据。

## 3. 统一语法入口的M1出口

目标链为：`版本化语法规则 + SourceSnapshot → 共享词法/无损CST → 严格AST投影 → 共享语义检查 → Checked HIR → MIR/各目标`。初始化、单函数编辑、声明/接口编辑、失败恢复及持久化恢复均从同一受版本约束的语法事实进入；AC/AV/A2R/A2C不得自行维护另一份Auto语法解释。

实现前先调查现有规则程序、scanner状态、projection、源码profile和消费者，核清旧auto-lex/旧parser中可提取的中立能力及其语义差异；不能机械抄旧耦合，也不能因为历史来源拒绝复用。通用平台若不能表达当前M1合法语法，须在本项扩展其机制并通过配置反控，不能削减支持面或永久回退另一套手写parser。允许迁移期差分路径；最终手写重复实现仅可作为明确隔离的测试参照，或已无独立语法规则的兼容门面，不能保留生产兜底。

| 门 | 必须观察到的结果 |
|---|---|
| SYN-01 规则与入口统一 | 当前M1已承诺及在途交付将纳入的源码profile、type/enum/方法/闭包等逐项登记；全部正式源码入口消费统一语法事实。共享前端不要求各后端支持同一特性超出原批准范围，不改原NA/accepted-diff。语法配置的关键字/优先级反控改变真实解析结果。 |
| SYN-02 fresh/编辑等价 | 同源fresh与逐次增量的AST、求值序事实、span和诊断等价；覆盖函数/方法/闭包体、type/enum与签名修改、跨声明和词法状态跨界。接口变化按完整依赖影响集合重验，拒绝、回退与资源耗尽具名，不以整模块重算冒函数增量。 |
| SYN-03 错误与恢复 | 无损重建逐字节相等；坏语法partial CST可查、严格投影不产Checked凭证；失败暖编辑不发布旧结果冒新结果，修复后可继续；迟到/取消不覆盖新revision。 |
| SYN-04 恢复与资源 | fresh/hit/restart/body-edit及恢复后再次编辑走真实入口；语法/codec版本及来源失配拒绝或miss并重验。深嵌套、扫描收敛、CST共享/回收与内存预算沿既有合同，禁止新增隐式固定句法深度上限。 |
| SYN-05 真实函数增量 | 未改函数parse/project/resolve/typecheck/HIR/lowering/后端生产为0；全局有界目录、词法重扫/恢复准入单列真实工作，不能靠不计数或只复用最终结果冒零生产。改变接口的受影响函数按依赖重做，不伪称全零。 |
