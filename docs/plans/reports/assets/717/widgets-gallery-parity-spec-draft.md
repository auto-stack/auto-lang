# Widgets Gallery 双端展示核验契约

## 范围

本契约适用于 auto-os 中的 `widgets-gallery` 示例画廊及 AutoUI Vue 与 VM/Iced 两个后端。画廊路由、页面源文件、预览卡片和生成的 Kitchen Sink 样例构成核验清单；本契约不要求两端像素完全相同。

## 清单与入口

- 路由清单必须从画廊源页面和路由定义解析，不维护第二份手写路由表。
- 每个面向用户的页面都必须可从首页卡片或侧边栏到达；特殊示例页须有明确入口。
- 每个页面在报告中记录路由、源文件、标题、预览卡数量、入口状态和四种后端/主题组合的结果。

## 示例可见性

- 每页的全部 `preview-card` 示例都必须能在首屏或滚动后看到，且标题、组件主体、属性说明和代码示例可读。
- 由 schema 生成的 Kitchen Sink 必须显示当前公共示例集合中的每个组件；非公开测试夹具应由生成器显式排除并说明原因。
- 菜单、弹层、日期选择器等需要动作才能展示的示例，须至少记录一组可见的打开或选择状态。
- VM 后端可用其原生控件表达 Vue 组件示例，但必须保留示例的主要语义与内容；简化实现应在核验报告中说明。

## 主题与显示

- Vue 与 VM 均在浅色和深色主题下逐页核验。
- 长页面须覆盖完整滚动区域；核查空白示例、裁切、遮挡、不可读文本和内容越界。
- 每个 route/theme 组合均保存截图或可复核的等价视觉证据，并记录运行错误、浏览器页面错误和截图采集失败。
- 允许组件 API 带来的有意交互差异；视觉与内容差异必须有说明，不能把缺失内容记作通过。

## 验收与记录

- 标准 verifier 应从源清单驱动 Vue 与 VM 检查，并输出机器可读结果和路线矩阵。
- 全部路由可达、标题与主内容存在、预览容器非空；每个 schema 示例被单独计数。
- 代表性状态动作应覆盖可交互组件族；测试工具无法定位内部控件时，须说明限制，并以截图证明初始示例仍可见。
- 报告记录适用 Rust 门禁和已在干净基线复现的测试失败；基线失败不得归为本次实现的通过或回归。
