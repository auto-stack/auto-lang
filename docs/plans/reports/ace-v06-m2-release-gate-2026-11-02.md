状态：用户已明确版本优先级，目标/发布门生效；本轮只更新规划，未实现、构建发行物、切默认、disable或发布。

关联：[v0.6路线](../../roadmap-v0.6.md)、[ACE版本合同](ace-milestones-version-boundary-2026-10-24.md)、[M2全替换合同](ace-replacement-first-m2-contract-2026-11-02.md)、[M1 A2C增补](ace-m1-a2c-scope-addendum-2026-11-02.md)。

## 1. 用户裁定与优先级

用户本轮明确：ACE M2应加入v0.6发布目标，即使牺牲一些发布进度（例如晚一周），也要替换为新版ACE，避免长期维护新旧两套编译引擎。

因此v0.6正式发布必须完成已批准M1（含A2C）和M2全替换/disable；仅有核心骨架、M1完成、语言能编译、部分入口opt-in或声明“替换就绪”均不足以发布。旧路线中“旧后端全迁移可延期”“v0.6先做基础子集/自举，产品退役以后做”等ACE排期由本裁定取代；Auto版AACE仍为v0.7方向，不加入本次发布前置。

M2范围沿REP-01..11：全部现有应用/模式/在用A2X目标与CLI/SDK/工具/宿主接管，工程级全局增量/真实热更新/Rust构建隔离、实际安装发行切换、新测试/证据迁移与旧实现彻底disable。本次不把M3/M4未来新增生态/能力加入v0.6，也不单方面取消其他主线的已批准合同。

## 2. 单一引擎的含义

v0.6正式产品只保ACE一套权威语义/编译执行体系：共享前端/受检HIR、查询/依赖/cache及Typed MIR/AV/native、HIR→各目标A2X provider。多个目标后端不是两套语言引擎；不得以“后端适配”继续委托旧AutoVM或旧AST Trans发射器。

旧执行/编译/转译实现、注册、构建/链接、工具、默认/隐藏开关、自动fallback与发行包中的旧binary全部退出。default/all-features和所有生产模式不能启用legacy；薄兼容API只转ACE。历史实现可从Git/独立已发布旧版本追溯与回滚，不能在新版内嵌一套旧引擎兜底。

中立值类型/诊断/资源与运行库、AutoUI渲染器和仍需使用的Rust库按真实归属保留，不按vm/trans目录名盲删；它们不得夹带旧执行循环或发射器。Rust实现的ACE本体也不是“第二套旧引擎”。

## 4. 发布时间与一周容忍

用户以“晚一周”为可接受的排期取舍示例：当前优先级是替换后再发布，不是承诺一周足以完成M2，也不是到了顺延日期就可以降低门槛。

仓库当前仍留2026年12月底/12月31日的早期窗口；v0.6路线§7同时说明§1.5月度建议不是重排后的承诺，其他文件还有后续范围收敛记录。本轮未获得新的绝对日期，不能把早期日期直接加七天写成已确认发布日。

下一轮容量/排期核算必须基于完整M2场景与目标/宿主/产品/disable缺口、当前已交付/在途/未立项、真实依赖关键路径、S/H写窗和跨仓消费者，并预留原规模回归、修复与发行验证。按此给出最早可信窗口及顺延约一周是否足够；若不足，如实提交缺口与日历调整，由用户决定，不暗改范围或自行承诺更远日期。

M2发布关键路径优先；不再为未使用的新生态、额外优化或仅展示的demo扩容拖延它。其他已批准版本线若与M2争用日历/机器/owner，显式列取舍并统筹，不通过自动取消他方Plan或抢占写面解决。到候选日门仍未过，则v0.6仍为未就绪，不以双引擎/旧引擎兜底作为“按期完成”。
