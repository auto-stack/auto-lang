# AutoOS 虚拟桌面：网站叙述与截图设计提案

日期：2026-10-09。状态：介绍设计提案，未实施网站修改、未部署。检查对象为当前仓内 website；没有据此宣称公网版本同步。

## 1. 判断与现状证据

用户提出的「先看深浅桌面，再由 Launcher 引入应用」应当保留。现有材料足以作为起点，但不足以让第一次访问的读者理解完整的桌面体验。主要缺口在叙述和图片组织，而非 Demo 数量。

- `website/zh/autoos/index.md`：完整桌面专题，展示之后立即进入窗口架构、独立工具、两张 Kanban 旧图、两张配置旧图；使用体验还未展开就转入产品组织与技术背景。
- `DesktopShowcase.vue`：四步文字先集中呈现，再共用一个 `ScreenshotGallery`。默认只显示浅色桌面，滚动不会自然遇到 Launcher、多窗口和工作图，后续能力依赖读者主动点击标签。
- `desktop-showcase.ts`：六图，其中两张桌面、两张 Launcher，只有两张应用场景；自由布局与分屏未做同组应用对照，虚拟屏无独立画面。
- `ScreenshotGallery.vue`：有键盘选择、原图及放大，这些能力值得保留；标签选择器适合一个章节中的状态对照，不适合承载整条叙述。
- `/zh/os` 有两主题桌面预览；适合作为入口。`/zh/ui-desktop` 介绍运行路径；适合留给开发者。完整产品体验应集中到 `/zh/autoos/`，英文同构。
- `demos.json` 恰有 28 个介绍项，六类：工作生活 6、阅读交流 3、媒体创作 6、系统数据 7、小游戏 3、应用结构 3。已有真实图、操作和运行条件。不要在 OS 页重新复制完整目录。

检查了已有网站截图及源图。旧 `desktop-shots/01-workspace1-productivity-grid.png` 有空白终端、错误日志和七窗拥挤，不宜作宣传主图；`06-natural-office-stack.png` 遮挡过多。现有 `06-productivity-dark.png` 有测试注释、函数探针和过长目录；`05-games-dark.png` 有初始棋盘和准备弹层。保留来源，但正式展示应整理真实演示内容并重拍，不能修图抹掉故障。

## 2. 主叙述：从一张桌面，展开自己的工作空间

读者的理解顺序：它长什么样 → 怎样找应用 → 应用怎样同时使用 → 怎样安排屏幕 → 怎样用来开发 → 怎样分开不同任务 → 还能做什么。

页面首句建议：**「从一张桌面，展开自己的工作空间。」**

引言建议：**「从壁纸、快捷方式和小组件开始，用 Launcher 打开工具，自由摆放窗口，或把它们排列成分屏。写代码、运行命令、整理文档，再把开发、阅读与休闲放进不同的虚拟屏，让每件事都有自己的位置。」**

引言下仅用一句交代当前形态：AutoOS 当前运行在宿主系统中；本文画面取自 VM 原生桌面。详细架构放在体验叙述之后。

## 3. 可直接使用的章节正文草稿

### 先让桌面成为你的空间

壁纸铺开，常用应用就在手边。快捷方式、任务栏与小组件组成桌面：看一眼时间和待办，再决定接下来做什么。浅色与深色呈现同一套桌面布局，你可以先从喜欢的外观开始。

图注只交代画面：浅色/深色 VM 桌面，无展开应用窗口。应用小组件按真实启动状态准备；现有 10 月 1 日图的待办和音乐来自已经启动并最小化的应用，不把所有小组件概括成同一种启动机制。

### 想用的工具，从 Launcher 打开

打开 Launcher，浏览应用图标，或输入名称寻找工具。先打开便笺，把一个想法写下来；再打开待办与日历，把接下来的安排放到眼前。

图外辅助说明：图标网格 / 名称搜索 / 键盘选择。Tab 可切换启动器展示形式，Enter 启动选中应用。以实际版本核对操作，不把网格里的图标数量写成 Demo 数量。

### 让窗口围绕手头的事

AutoEdit 占据主要空间，系统日志与 AutoMusk 错落放在旁边，音乐留在角落。拖动窗口、调整大小，让代码和辅助工具各有位置；点选窗口切换焦点，从任务栏回到刚才的工作。

本节介绍手动移动、调整大小、焦点与任务栏切换。按用户补充要求，使用实际打开的 AutoEdit、系统日志、AutoMusk 与音乐播放器四窗实拍；AutoEdit 是视觉主位。AutoMusk 此处为初始会话界面，不作为 AI 执行过程或已完成结果的证据。原俄罗斯方块、纸牌接龙与扫雷参考图只出现在 06 的第三个「休闲屏」标签，日期与构图参考身份随图切换。

### 从自由摆放，到有序分屏

需要同时对照多个应用时，选择一种分屏排列。主窗口与侧栏让便笺占据左侧，待办和日历放在右侧；四格网格则为文件管理器、系统监视器、像素画板和计算器各留一格。把相关信息并排放好，减少窗口之间的遮挡。

按用户 2026-10-09 补充要求，网格采用另外四个应用，不复用便笺、待办和日历。主从体现主任务与辅助信息，网格体现四个用途各有位置；按两种使用场景叙述，不称为同组应用的前后对照。两种布局均从真实排列入口切换，不能只靠手动摆成几块宣称一键排列。

### 把代码、命令和文档放到手边

一个小项目，从代码到说明文档，都需要合适的工具。用 AutoEdit 浏览和编辑文件，用 AutoShell 运行命令、查看结构化结果，再用 JadeEdit 写下设计与使用说明。让相关资料同时可见，切换工具时也能继续手头的事。

配图展开四个小段，沿用同一个项目，而非四个彼此无关的产品海报：

1. **编辑代码 / AutoEdit**：打开项目文件树和两三个相关标签，主编辑区显示可理解的一段界面逻辑或配置。图外一句「从文件树到代码，定位正在修改的内容」。
2. **运行命令 / AutoShell**：显示实际输入和有意义的输出，例如浏览目录、筛选文件或检查 JSON 数据。图外一句「运行一条命令，再把结果看清楚」。AutoShell 有结构化语言与结果，不能用 AutoTerm 的终端图代替。
3. **整理文档 / JadeEdit**：打开同一项目的 `.ad` 设计说明，能读到小标题与内容；用第二个状态展示链接/反链或搜索，聚焦一项实际可用功能。图外一句「把这次工作的思路写下来，再连到相关资料」。JadeEdit 与旧 Jade Garden 是不同产品，不挪用旧 Garden 图。
4. **推进一次变更 / AutoMusk（可选实拍）**：继续这个项目的一个小需求，例如为待办列表增加完成项筛选。选取真实计划、工具活动或阶段报告，单独给一幅大图，说明「从需求进入计划，检查改动过程与阶段结果」。只有实拍能证明复审与交付完成时，才展示相应结果；不把尚未完成的运行写成自动完成的闭环。

阅读节奏是先看开发场景，再沿着「代码 → 命令 → 文档 → AI 辅助变更」理解各工具。章节内用三个紧凑的工具段和一个可选 AutoMusk 宽幅段，避免把四个窗口挤在一张缩略图中。每段末尾链接 `/zh/apps/autoedit/`、`/zh/apps/autoshell/`、`/zh/apps/jadeedit/`、`/zh/apps/automusk/`。

开发主图的目标构图：AutoEdit 左侧约 55–60%，AutoShell 右上，JadeEdit 右下；须先验证三者在目标桌面版本可真实启动与排布。若当前只能以独立原生窗口运行，先使用独立应用实图并明确说明，不能将它们拼成虚假的桌面集成截图。正文中的「同时可见」也随实际支持调整。

### 给不同的事情，一屏空间

把笔记、待办和日历留在第一屏，再到第二屏打开小游戏。通过桌面切换器回到工作屏，刚才的窗口仍在那里。不同的事情拥有不同的空间，眼前只留下当前要关注的内容。

「工作屏」「休闲屏」是网站的场景标签。当前实际系统名称是 Desktop 1 / Desktop 2，不宣称已有重命名功能；「虚拟屏」首次出现时补充「独立的桌面工作区」，避免与外接显示器混淆。

正式素材若验证了开发工具的桌面集成，这一节改为「把代码、命令和文档留在开发屏，再到另一屏阅读或休闲」，自然延续前一章。当前样稿仍用已核查的日常工作屏，不从独立应用截图推断其虚拟屏行为。

### 工作之外，也有阅读、创作和片刻休闲

一张桌面还可以承载阅读、图片、音乐和系统工具。我们从 28 个 Demo 中挑选了几组场景；选择感兴趣的方向，继续查看真实界面、典型操作与运行条件。

精选卡片用可理解的动作：「读一页书」「记录一个想法」「画一个像素图案」「查看文件与系统状态」。避免只有应用名的图标墙，也避免把应用范围扩写为已具备跨应用自动化。

## 4. 页面视觉与节奏

- 保留站点紫色品牌和深浅主题令牌。完整桌面专题建议采用宽图阅读结构：文字仍为约 720px，主图扩至全站现有 1200px 上限；这是专题布局提案，不修改通用文档页宽度。
- 主线每节一段 50–100 字、一幅主图、最多三条短标注。01/04/05 是有限状态对照，其他主图随滚动直接可见。不要把主线藏进总图集或自动轮播。
- 01 用全幅桌面奠定氛围；02 可用较紧凑的左右图文；03–04 回到宽图；05 用开发主图和三个应用细节逐层展开，AutoMusk 另给宽幅过程图；06 回到虚拟屏宽图；07 用轻量 2×2 场景卡结束。卡片承载并列选择，主线正文不套一层层卡片。
- 桌面深/浅对照是截图状态，和网站主题切换分开；选择截图不会切换真实桌面的状态。按用户 2026-10-09 补充要求，默认展示深色桌面，浅色作为备选；深色按钮排在前面，主线其余桌面图也优先沿用深色。
- 配图保留完整边界与任务栏，不使用伪浏览器窗套住 VM 桌面。缩略图可使用已核验的局部裁剪，但提供完整原图；标注放图片外，不涂改截图。
- 手机按正文→截图→标注顺序。390px 下全幅图只能看结构，关键控件应配独立局部放大图及原图入口；不能以缩小整幅图作为全部移动端介绍。
- 首图及时加载，其余延迟加载并给尺寸占位。正式 Web 版本从无损源图生成 WebP/AVIF 展示件，原 PNG 保留作放大来源；现有单张桌面 PNG 约 5MB，不宜让九张原图同时首屏下载。
- 导航使用现有阅读目录即可，不额外叠两层吸顶条。英文长度、键盘、Esc 回焦、减弱动态偏好沿用网站规范。
- 页面中只有一处简短「当前运行形态与范围」，再由图注标明必要的内置数据、素材与日期；详尽成熟度说明在现有 Apps 条目，避免每节重复免责声明。

## 5. 截图分镜与拍摄标准

桌面核心素材维持 9 张：桌面浅/深 2，Launcher 网格/搜索 2，开发自由窗 1，日常应用主从 1，另四应用网格 1，休闲虚拟屏 1，切换器 1。工作屏画面复用主从图，不再多拍一个重复工作图。精选场景从现有 28 Demo 素材取 4 张。

开发章另计：真实开发桌面主图 1（集成核查通过后）、AutoEdit/AutoShell 细节各 1（可先复用已有实图）、JadeEdit 细节 1、AutoMusk 过程图 1（可选）。全部准备齐时共 17–18 个源素材；开发细节采用章内选择或逐段图文，避免将所有图片同时展开成图库。若主图或可选图尚未核查，实际使用数量相应减少。
