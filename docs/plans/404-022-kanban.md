## API 端点（`src/back/api.at`，委托 db.rs）

| 方法 | 路径 | db 函数 | 说明 |
|---|---|---|---|
| GET | `/api/cards` | `all_cards()` | 列出全部卡片 |
| POST | `/api/cards` | `create_card(title str)` | 新建（默认 column:"todo"，自增 id） |
| DELETE | `/api/cards/:id` | `delete_card(id int)` | 删除（整体重建 List） |
| PUT | `/api/cards/:id/move` | `move_card(id int, column str)` | 移动到指定列 |

**a2r 规避**（套用 018 db.at 范式，实测有效）：`move_card`/`delete_card` 返回路径用 `var result T = T{...零值...}` 预声明 → handler 内 `let moved = T{...全字段拷贝...}` → `result = moved`；迭代体内借用字段用 `let kept = T{...全字段...}` 重建（触发 a2r clone）。生成的 db.rs 验证：`card.id.clone()`/`card.title.clone()` 等正确克隆。

## 过程中发现的关键问题

### 1. 端口缺口（重要，影响 019-027 全部后续示例）
`pac.at` 的 `front_port`/`back_port` 已在 `pac.rs` 解析、`automan.rs` 有 `pac_dev_ports()` getter，但 **`auto run`（`run_vue`/`run_vue_project`）当前未调用它注入环境变量**，`main.rs` 也无 `-F`/`-B` CLI 参数定义。结果：`auto run` 仍默认 3000/8080，pac.at 端口声明不生效（018 README 描述的 `-F`/`-B` 与自动注入当前未实现）。
- **临时方案（022 已验证可用）**：环境变量分离启动——后端 `AUTO_HTTP_PORT=80NN ./app-NNNN-back.exe`；前端 `cd gen/front/vue && AUTO_FRONT_PORT=30NN AUTO_HTTP_PORT=80NN pnpm dev`。
- **playwright baseURL** 用 `http://localhost:30NN`（vite 默认监听 IPv6 `[::1]`，`127.0.0.1` 连不上）。
- **根治建议**：在 `run_vue_project` 调 `pac_dev_ports()` 并 `env::set_var("AUTO_FRONT_PORT"/"AUTO_HTTP_PORT")`，属独立 codegen 改进。

### 2. R006 `:key` warning（for + if 模式）
`for card in .store.cards { if card.column == "todo" { row{...} } }` —— `for` 的唯一直接子元素是 `if`（非 Element），codegen 不加 auto-`:key`（仅 `body.len()==1` 且为 Element/Component 时才加，见 `vue.rs:3707`）。功能上对增/删/跨列移动正确（Vue 就地复用），仅同列重排会有 DOM 复用问题——阶段 1 不含重排，可接受。根治需改 store 预派生三数组（让 for 体直接是 Element），留待阶段 2 或 codegen 改进。
