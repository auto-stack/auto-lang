## 3. a2r 认证合同（冻结）

- **生成形态（实测）**：`fn main() int` → `// Auto-generated by a2r transpiler\n\nfn main() -> i64 {...}`。
  旧引擎 int=i64，生成的 `fn main` 返回 i64——**不能直接作 Rust 入口编译**。
- **认证包装（冻结）**：生成文件 byte-identical 落盘为 `generated.rs`，独立 wrapper：

  ```rust
  mod generated {
      include!("generated.rs");
      pub fn entry() -> i64 { main() }
  }
  fn main() {
      let observed = generated::entry() as i32;
      println!("i32:{}", observed);
  }
  ```

  生成 Rust 永不被改写；wrapper 是独立宿主文件，其全文 hash 计入认证键。参考侧
  `reference/*.rs`（手写，带 assert + `println!("i32:...")`）与 actual 侧输出必须
  各自等于同一固定 oracle `i32:<十进制>\n`。值域注意：`as i32` 属包装观察编码，
  超 i32 值域的行按语义差异行处理，不得靠截断变绿。
- **认证键（冻结字段）**：golden 全文件集 hash + actual 全文件集 hash（必须相等才进入编译）、
  wrapper 全文 hash、固定 oracle 文本 hash、参考文件 hash、rustc 版本+target+生效 flags、
  依赖闭包（基线=纯 std，无外部依赖；出现依赖时记 lock 闭包 hash）、来源转译器身份（仅审计，不作失效轴）。
- **复用规则**：转译器变更但输出与上下文（golden/oracle/wrapper/参考/toolchain/依赖）不变
  → 复用证书不重编（G03）。任一失效轴漂移 → 证书 STALE，日常不自动重认证（G05）。
- **预算（实测冻结）**：scalar 案例 rustc `-O` 编译 0.12–0.19s/例。冻结上限：
  编译墙 120s/例、运行墙 30s/例、输出 cap 1MB/流、认证 scratch 必须在显式 -OutDir 下
  并整体清理；全部进程置于 Job containment（沿用 788/818 contained 工具治理）。
- **日常快照**：`spawn rustc/cargo/目标 Rust 进程计数 = 0`（G02，按进程创建计数核查）；
  金样漂移只 FAIL + 生成待审 proposal，绝不自动更新金样（G04）。
