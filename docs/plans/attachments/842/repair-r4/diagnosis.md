# PLAN-842 R4：Cargo 路径图诊断与最后一次自动修复范围

独立最终复审连续 R2、R3、R4 为 needs_fix。此前 [R3 诊断](../repair-r3/diagnosis.md) 已记录受管闭包和复制期一致性；本轮 [R4](../review-r4/report.md) 证明新增非受管检查仅验证文件存在，不能证明 Cargo 路径图可解析。修复前必须同时处理 R4-01/02，不能只追加旧正例。

## 实际不变量和根因

- 用户提供的非受管语言/UI 来源：直接和传递本地路径依赖的目标 Cargo 包身份与声明一致，`package` 重命名和 workspace 继承按 Cargo 语义处理；显式版本约束必须与被选中包的真实版本兼容；普通/构建依赖图不能有 Cargo 拒绝的环。目标条件依赖仍应解析；合法仅通过 dev 边闭合的环必须允许。注册表依赖不得强制联网或调用 Cargo 才能生成。
- 实际生成工作区和正式交付两条路径都必须在写旧产物之前执行相同结构准入；坏源失败具名，旧 workspace/app 或旧交付逐字不变。仅在工作区入口检查不能证明交付安全。
- 当前 DFS 只用 visited 集防无限遍历，漏掉普通环；仅取目标 manifest 自己的包名验证，未与声明键、`package`、继承的版本约束比较；已有测试把普通环误当合法控制，未以 Cargo 的离线 metadata 区分 dev 环。交付入口对非受管语言根仍只做目录/清单存在性检查。

## 调整与差异化 oracle

1. 将包节点与路径边分类建图，验证目标 `package.name`、声明键/显式 `package`、workspace 继承，以及 Cargo semver 版本约束（含 workspace package 继承）。仅对普通和构建边的环拒绝；包含 dev 边的合法环正控必须通过。目标条件、已关闭 feature 的路径和缺失源均须与实际 Cargo 对照，避免只用字符串相等或拒绝所有重复节点。
2. 在开发生成和正式交付共用结构准入，先于任何输出写入；受管安装继续使用冻结收据及 staging 字节验证，不对普通开发工作树引入收据或网络依赖。
3. 真实 CLI 与离线 `cargo metadata` 配对：普通环、错误包身份、错误版本、坏继承、UI 错身份各应拒绝且旧文件保留；dev 环、`package` 重命名、正确 workspace 继承与版本均应成功；正式交付普通环同样拒绝。保留 R1–R3 全闭包、缺收据、staging 漂移与 21 测试迁移选择控制，实际安装和最终版本重新绑定。
