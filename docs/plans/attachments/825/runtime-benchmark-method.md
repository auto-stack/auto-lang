# Proposed Spec delta SD-05: runtime benchmark method

Status: proposed for merge, not canonical Spec content.

- Freeze binary identity, input hashes, profile/wire/semantic versions, engine
  versions and flags before comparing runtimes. Measure on one machine in a
  single instance; retain every sample and failure rather than deleting
  outliers to obtain a preferred result.
- Required engine groups are AV reference, AV LoadedProgram, V8 JS Ignition,
  V8 Wasm Liftoff, and V8 Wasm optimizing tier. Tier claims require direct
  evidence from the measured binary: generated bytecode, `using Liftoff`, and
  `using TurboFan`. Flag presence alone is not evidence.
- Workloads are checked integer accumulation (500500), short block chains
  (B=1/8/64/256/1024 returning 42), a 1024-increment long block (1024), and
  direct/recursive sum(32)=528. Expected results are independent of all
  engines. Equivalent public non-overflowing subsets are used; MIN/-1 and
  signed-division differences belong to separate semantic cases.
- Each workload/engine measures load, first execution, 10 warmups, and 30 hot
  samples. Process peak and loaded-index accounting are separate rows.
  Publication includes p50/p95/p99, min/max, mean and variance with raw JSONL
  and raw-file hashes. No speed percentage or universal winner is promised.
- A run is incomplete if any required engine/workload/tier, phase, result,
  process peak, or raw sample is missing. Zero-selected, ignored, duplicated,
  fake-tier, erased-peak, and wrong-result controls must make the parent gate
  nonzero. Unknown tools or tiers are gaps, not passes.
- The original 798 editing workload remains a separate hard gate: P95 below
  one second and the original managed/process memory limits. New benchmark
  microcases do not replace that workload or its dual-line memory evidence.
  AV worker measurements use `--release`, matching the established 798 formal
  runner; debug-worker timings are never substituted for that contract.
