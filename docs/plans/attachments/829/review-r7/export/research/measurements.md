# AGP Measurements (T-07, V-05/V-07/V-08)

Machine: Windows x64, NVIDIA GeForce RTX 4060 Ti, **Vulkan**, driver NVIDIA
617.14, DPI 2.0 desktop. All numbers below describe THIS machine only — no
cross-platform or competitor conclusions are drawn. GPU timestamp queries are
**unavailable** (`gpu_timing_available: false` in every report); no GPU-side
frame times are claimed anywhere.

Raw reports: `scratch/829/lifecycle/report.json`,
`scratch/829/metrics/report.json`, `scratch/829/negative/report.json`
(+ `negative-sabotage/` for the broken-verifier demonstration).

## 1. Methodology (honest bounds)

- **CPU frame time**: wall clock around `{canonical sim ticks + wgpu encode +
  queue submit}` per rendered frame, offscreen, two alternating 900×600
  views, no swapchain pacing. P50/P95 over 300 frames per run. This measures
  the present-loop cost up to submission, NOT GPU execution time, and NOT
  windowed present pacing.
- **Cold vs warm**: cold = first pass in the probe process; warm = second
  pass on the same device (meshes/pipelines already resident).
- **Accounting (r1 F08 repair)**: resource CREATIONS (new GPU objects,
  instrumented store deltas) and buffer REWRITE bytes (instrumented at the
  actual write paths — quad instance buffer; 3D camera+light+instance
  buffers) are measured SEPARATELY. Pipelines/views/scene are built ONCE
  before the passes: cold = first pass in the process, warm = second pass
  with everything resident. Raw per-frame series is persisted as
  `frames_<game>_<pass>.json` next to the report; the summary quantiles are
  computed from that series and cross-checked against the instrumented
  totals (a sabotaged counter makes them disagree → the run is RED, recorded
  in `scratch/829/metrics-sabotage/`).
- **RSS**: PowerShell `WorkingSet64` samples — a noisy secondary signal
  paired with explicit resource counts, never the sole release oracle.
- **Thread observation**: PowerShell `(Get-Process -Id PID).Threads.Count`.
  AGP spawns no owned worker threads (static audit of the runtime path);
  wgpu/winit runtime threads are not AGP-owned workers.

unexecuted gate is never green.

## 5. Deviations / notes

- Lifecycle and metrics run **headless offscreen** (mode recorded per
  report); the interactive windowed cases remain the windowed evidence.
- **Lifecycle (r1 F06 repair)**: all counts are derived measurements —
  DropWitness lifetimes for views, real GLB mesh uploads per game (flat after
  build across 20 restart rounds), a real looping audio stream surviving
  retries (frozen autoload semantics), per-session cache bindings (within-
  round creations = 0), thread/RSS sampled BEFORE the workload, AFTER the
  workload, and AFTER device teardown, close-during-load awaits an abort
  callback acknowledgement (`Err(BufferAsyncError)` observed), and the iced
  case now closes normally (verdict returned after event-loop exit). The
  review's `mem::forget` injection is a permanent unit test
  (`renderer::witness::tests::witness_detects_forget_leaks`). 20 restarts windowed would add no signal beyond the
  offscreen path — the reset semantics are host-level, not swapchain-level.
- The squash lifecycle baseline is driver-state (the squash sim keeps no
  scene-graph objects by design); breakout's is scene-object count (60).
- `metrics` frames do not include swapchain present pacing (headless); the
  windowed cases' present loops remain uninstrumented by choice — the V-07
  contract is fixed-device replay comparability, which the offscreen numbers
  serve.
