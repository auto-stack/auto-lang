## 2. 原始字节通道（raw fence locator）

规则与树解析器逐字对齐（探针全 PASS）：

- 行首 indent<4（空格=1、Tab=4，复刻 `indentWidth`）；开启行 = trimmed 行以
  ≥3 连 `` ` `` 或 `~` 开头（info 任意）；关闭行 = trimmed 行**恰好**为同长度
  同 marker 纯串；嵌套围栏由"首个未闭合开启者吞到其关闭行"界定。
- 载荷 = 开启行 EOL 之后到关闭行行首的原始 bytes（含关闭行前实际存在的全部
  末尾换行；混合 CRLF/LF 原样保留）。
- 探针覆盖：CRLF 混 LF、四反引号内三反引号、空 fence、载荷/关闭行尾空格、
  源内标题、行中缀 ``` 不误判、4 空格缩进行不开 fence、`^anchor` 提取、
  树 fence 数/info/文本 与 raw 定位一一对应（规范化后逐字节相等）。
- 未闭合 fence：locator 报 `closed=false`、载荷到 EOF；协议层按设计判 ERROR。
- 设计决策：外仓 `BlockNode.source` 恒 `rng(0,0)`（parser 从不填充）——树只
  提供结构语义（heading 层级/anchor/fence 顺序/info），载荷字节一律走 raw
  locator；逐 fence 对应失败即 ERROR（设计 §7.1 的 fence-aware 通道成立）。

## 3. AVM 观测边界（`run_with_capture_and_path`）

- API：`run_with_capture_and_path(code: &str, path: &str) -> AutoResult<(result_display, stdout)>`
  （lib.rs:433）。`.as` 由 path 后缀触发内部 lowering（`#[rust]` pragma 豁免）；
  E5501 `.at` 方言门以 path 扩展名参与。
- panic 穿透：VM 线程 panic 经 `join().unwrap()` 在调用方重 panic——adapter 必须
  `catch_unwind` 并判**基础设施 ERROR**（非语言错误）。
- entry：无显式模式 API；`main`/`test` 符号自动优先，否则顶层脚本；末值/返回值
  经 `extract_autovm_result` 呈现为 result。实证：`fn main() int { return 2+3*4 }`
  → result `"14"`（program entry 的 result 通道成立，探针 [PASS]）。
- 错误分类（**变体法，不做字符串猜测**；`AutoError` 公共枚举）：
  - `parse` = Lexer*/Syntax*（常包 `MultipleErrors` → 递归取首错；实证
    "unexpected token"）；
  - `type` = Type/Name/Comptime（实证 "undefined variable"）；
  - `run` = `Msg`（排除 `auto_gate_` 前缀）；实证消息形：
    `DivisionByZero at line 3 (ip=0x002d)`、
    `RuntimeError("Array index 10 out of bounds (array length: 3)") at line 2 (ip=0x003c)`；
  - `link` = MsgWithSource；`gate` = Msg(`auto_gate_…`)；Io = io。
  - miette `Diagnostic::code()`（如 `auto_syntax_E0001`）在 auto-lang 内部可直接
    使用（既有依赖）——T-04 强诊断以 code 为准，不以 message 猜。
- 类型宽松实证（支持表如实登记，不虚报）：`1 + "s"` → Ok `"1s"`；
  `fn f() int { return "s" }` → Ok 打印 `s`。即本管线返回类型/运算类型不强制，
  "type 阶段"仅覆盖 name/语义检查；试点不设"期望 type 错误"用例。
- legacy-display 取值事实（`extract_autovm_result`/`format_value_for_display`）：
  顶层 int/string 不带引号、嵌套 string 带引号、Uint `u` 后缀、Byte `0x%02X`、
  bool `true/false`、object 键字母序、列表 `[1, 2, "s"]`；比较 = 精确 String、
  无 trim（stdout 同）。legacy `expected.error` 只验"任意 Err"（弱 oracle，
  `03_uncaught/expected.error` 实为空文件）；legacy 失败时写 `.wrong.*` 回
  fixture 目录（新协议改写隔离 scratch）。

## 4. a2r 观测边界

- 单文件：`transpile_rust_with_source_dir(dir, name, code) -> AutoResult<Sink>`，
  `Sink::done() -> &Vec<u8>`；内存态；`name` 对产物字节惰性（legacy 以 stem 派生
  name 仅为元数据，T-05 沿用保持对账一致）。探针 [PASS]：hello 与
  use_c_static 发射与 `.expected.rs` **逐字节一致**。
- `use.c` manifest：相对 source_dir 解析；**manifest 缺失时静默忽略并产出不同
  字节**（探针实证 5486 vs 175）——a2r adapter 发射前显式核验 case 引用的
  manifest 存在，缺失 = 合同 ERROR，不静默通过。
- 多文件：`transpile_rust_project(entry) -> HashMap<String,(bytes, sourcemap)>`；
  `use` 发现跳过 `use.c/use.rust/use.auto.*`，`mod.at` 目录扫描 `.at`；产物键
  `main.rs/db.rs/api/mod.rs/api/handlers.rs/Cargo.toml`（探针 [PASS]）。
  **project 产物 ≠ per-file 金样之和**（project `main.rs` 含 `mod db;` 等声明；
  legacy 对 project 腿只断言键集+声明，无字节金样）——多模块 case 的 oracle 按
  project 模式独立评审建立（§5.4 新 oracle 规则），探针 4 个 [FAIL] 即此差异。
  **T-05 补充发现**：project 模式 `Cargo.toml` 的 app 名派生自入口**父目录名**
  （fixture `005_multi_file` → `app-005_multi_file`，物化目录 `project` →
  `project`）——路径派生元数据属于输入身份；适配器物化到固定的
  `<case>/project` 目录使该派生确定化，oracle 以"对同一物化布局的直接调用"
  建立等价（T-05 测试锁定）。
- 栈实证：use_c_static 发射在主线程（debug、8MB 栈）**栈溢出**；128MB 线程通过
  ——a2r adapter 一律在大栈线程（≥64MB）执行发射，与 auto-lang 自有 sync
  wrapper 同式。

## 7. AtomParser 与合同解析

- `AtomParser::parse(&str)`（auto-atom）支持节点/对象/数组/原始值/注释——语法
  满足设计 §4.2。
- **`Obj::set` = `IndexMap::insert`（upsert），重复键在解析内部静默丢失**——
  不满足"重复键在丢失前检测"。
- 冻结决策：`auto-test-case` 自带 strict Atom 子集解析器（同语法；重复键/
  未知形态显式 ERROR；不执行 Auto 代码）；与 AtomParser 对拍（合法输入同构）
  纳入协议测试（V-01 面）。设计 §4.2 的"采用 AtomParser 子集"按此理解为
  采用该语句子集 + 严格化读取层。

- 执行边界沿用计划 §5.3：pilot 不承诺通用 deadline/进程树隔离；测试 harness

## 9. 支持表（v1 pilot 冻结）

- schema：`autolang.case/1`、`autolang.suite/1`。
- source：`block`/`file`/`text` 恰一；syntax：`auto` | `auto-script`；虚拟相对
  path 必填、文件内唯一。
- entry：`script`（顶层，result=末值 display）| `program`（main 自动优先，
  result=main 返回值 display）；`expression` = script 单表达式形。无模式强制
  API，按 §3 事实登记。
- adapters/actions：`avm/run`；`a2r/emit`（单文件与 files 多文件→project 模式）。
- comparators：`bytes`（默认）| `lf`（仅 CRLF→LF）| `legacy-display`（VM result，
  不 trim）| `exact`/`substring`（有限 message）。
- expect 观测：completion、result（legacy-display）、stdout/stderr（bytes；
  未声明=未检查，`text:""`=检查为空）、diagnostics（stage+code 或有限
  message）、artifacts（逻辑路径集合 + 逐项 bytes；缺失/额外均 FAIL）。
- 状态：PASS/FAIL/ERROR/BLOCKED/SKIP/NOT_APPLICABLE/UNDECLARED/NOT_RUN；
  XFAIL/XPASS 本期 unsupported ERROR。
- unsupported（显式 ERROR，不解析后忽略）：variants、relations、recipe、
  product_from 下游消费（无编译腿）、budget/fixture/env 声明、native/ac/acc、
  platform 声明。
- 资源/准入：§8 表。
