## 1. 定位与本轮决定

拟将`auto-web`作为与auto-ui、auto-man同级、可独立构建/测试/发行和持续开发的仓，负责Auto的Web服务框架及工具链。API生成属于其中一个能力，不是仓的全部定义。

本轮确认排程：**884完整收口 → 887测试治理完整交付 → auto-web有限迁移完整交付 → UI/Man结构工作包 → 核近期有限收口及新增Web交付**。885和应用按原合同继续，只在实际写面交接；不以Web迁移作为885、BLOG-004或全部ACE工作的额外前置。

`auto-web`仓尚未由本会话创建、交付或发布。实施前核真实已有目录、远端身份、refs/历史、许可证、默认分支及WIP，再决定承接方式；若已有仓须保全并沿用身份，不能清空/orphan/强推或创建替代仓掩盖历史。若确为新仓，在后续明确实施授权内建立；本设计不是建仓授权。仓名不预先等于包名、crate数量或公共registry名称。

### 与Design31的命名关系

[Design31](31-autoscape-autoweb.md)的AutoWeb是更广的网络应用体系，AutoScape为浏览器/应用容器产品；其浏览器、Realm/沙箱、网络分发和远程运行仍属原远期范围。本文的auto-web是该生态中**服务端框架仓首期**，不自动接管或提前启动Design31全部能力，也不更改AutoUI/AutoDown领域归属。

## 3. 目标依赖方向与单源规则

按逻辑职责分层，不在本轮预设多个细crate：

1. **Web合同/纯政策**：路由、参数/响应、错误和服务配置，依赖必要轻数据，不依赖VM/renderer/Man管理。路由合同和版本各一份。
2. **Web生成/运行**：服务与HTTP客户端生成、框架路由/绑定/生命周期；通过公开语言元数据/转译/执行接口接SDK，运输与VM专属桥分离。
3. **适配与装配**：Web侧语言adapter可以依赖语言SDK；产品/CLI宿主在上层组合Web与语言。语言基础SDK不反依赖Web实现，Man管理核心不因Web引入完整VM/renderer。

依赖为产品/CLI装配→Web公开工具或合同、Web语言adapter→语言SDK/中立基础；UI→Web客户端/轻合同和语言SDK。Web正常/必需测试闭包不依赖auto-ui实现、auto-man管理、Tauri或其主检出。跨仓消费者验证可显式带相应仓，不冒充Web基础闭包。

现有HTTP服务若依赖Core私有VM状态，必须在函数/调用链级分开领域算法与语言专属执行桥，再选择既有公开端口或最小中立端口。类型/trait按所属领域唯一，跨边界转换显式且保真；不得复制VM/TypeStore/AST/服务配置，也不得通过扩大pub私有内部或循环依赖“完成拆分”。无法证明端口方案全路径可行时，正式Plan先有有界探针/决策门，不直接承诺机械迁移。

上层组合/兼容门面可以有期限地依赖Web；基础SDK不得借门面隐藏反向边。每个兼容入口有消费者、版本、退出或长期支持合同；保留重导出不等于保留第二份实现。

## 4. 首期迁移范围与排除项

首期交付一个**完整服务框架迁移包**，内部完成边界提取、目标仓承接、生产切源、旧实现清理、测试/发行和真实消费者，不为每个probe或函数取号。

| 包内范围 | 必须交付 | 不能当作完成 |
|---|---|---|
| 服务合同与单一政策 | 冻结已支持路由/参数来源、错误与响应、配置/profile/版本、预算及身份；领域owner清楚 | 只新增DTO/目录，生产仍用旧实现 |
| 真实HTTP生成/运行 | `.at`经正式工具生成Rust服务、真实编译启动；VM轨经正式语言adapter工作；适用合同和错误语义保持 | 只比生成文本、运行旧缓存、手修生成Rust或用fake后端 |
| Man/UI消费切源 | `auto service ... --server vm|rust`、现有`auto run`相关服务链经正式Web入口；Web客户端真实供应用/UI消费 | 改命令名、丢旧flags/错误码/stdio/cwd/取消或让应用改写业务以适应搬迁 |
| 仓库与发行闭包 | 固定SDK/锁/工具/模板/资源、独立构建测试、生成工程外部消费、重定位及失败恢复 | 大workspace可编译、依赖D:/autostack绝对路径、旧target/rlib或隐式兄弟WIP |
| 测试与旧来源退出 | 继承887身份/映射、用例与oracle随owner迁移、批量/定向入口登记、源目标映射和旧重复实现实际清理 | 复制到新仓却保两套算法、重新生成baseline接受丢测试或把移仓算净删 |

**首期保留现有安全与生命周期支持面**：已有严格配置、CORS、Host允许表、单层可信代理、已支持鉴权策略、限流/预算、健康/就绪、有界观测、SSE/文件/上传及请求/handler/关闭合同，按现行Spec逐项冻结后保持。既有能力不能因“认证/监控后续扩展”被延期。支持等级继续沿用本机及受单层代理保护等既有合同，不自动扩大到直接公网、内置TLS、HTTP/2/3、多层代理或新OS生产认证。

现行命令是`auto service`；`auto serve`维持原daemon语义。部分源码注释仍用serve称服务，不能据注释错误改公开命令。端口冲突/非法配置须非零，不杀用户占端口进程、不静默换端口；ready必须指向本次真实服务及有效配置，implementation/generation身份与effective-config身份分开。

首期不新增：完整OpenAPI、额外语言SDK/客户端生态、扩展认证/依赖注入/中间件体系、扩展可观测/部署平台、浏览器/沙箱/远程运行、UI新架构、ACE新能力。现有HTTP客户端生成是迁移范围，未来SDK扩展不能混同为本期全部排除；现有通用HTTP客户端/JSON/socket等语言基础能力不整批外迁。

## 5. 测试与真实应用消费

迁移时使用887正式交付清单、逐ID/check账本、原source/oracle与已验证入口；887保持原三仓+ACE范围，不被本设计追加四仓实施。迁移包负责新增Web owner、独立档位与四仓组合调度、选择守卫、迁移/批准退役映射。根语言档不测试外部仓成员，迁出测试不能只留下再导出壳便算已覆盖。

验证分三层：Web合同定向测试；VM/Rust两服务轨真实HTTP契约对照；应用消费。对照用同一业务输入与独立预期，响应状态/header/body/错误、数据写入和适用流/文件/生命周期分别观察；非确定性时间/路径字段仅按原已约定规则比较，不能粗暴删字段使对拍绿。缺能力/既存红/环境/未执行保留，新增红0；必需正控未跑不能认证交付。

Blog是首个真实应用候选：固定纯`.at`业务与数据根，通过新归属的生成/运行工具验证创建、回读、修改、陈旧rev拒绝、失败保稿与重启恢复。**BLOG-004原合同是Vue+Rust和原生VM界面+Rust后端**；这两条证据不能证明VM/Rust两服务后端对等。本迁移包自己拥有两服务轨的独立fixture与HTTP对照；Blog是否现有同源业务已支持VM服务轨，正式冻结前先核。若未支持，不为迁移擅改Blog业务/扩大BLOG-004，也不声称Blog两后端均已验。

已有Blog双UI证据在源/配置/依赖/工具身份均适用时可复用；迁移影响的消费链定向重放，GUI/机器窗口按原纪律安排。BLOG-004无须等Web迁移才完成；Web不能等BLOG-004全部完成才开发，否则将应用UI问题变成框架全局门。

work/review仅触面反例/模块/必要check；独立final pass后merge按各实际修改仓冻结门统一执行，完整批次机器级单实例，优先按现有冻结组合接口及输入一致性复用，不重复整档。原始证据本地、摘要记录命令/退出码/选择与执行数/路径/hash；不入库大日志和截图。
