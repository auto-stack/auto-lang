# AutoDown / Typst 排版：v0.6 阶段设计

> 2026-10-16；目标态草案，未实施、未测试 Typst。来源为 AutoOS《AutoDown支持Typst布局》；复用 [AutoDown 统一文档引擎](../../../../auto-down/docs/designs/09-unified-document-engine.md)，互操作继承[Design41](../41-interface-metadata-and-foreign-abi.md)。

## 1. 定位与复用边界

为 AutoDown 提供高质量布局、分页/导出及可测的增量更新能力。保留现有文档块模型和编辑器职责，排版后端作为消费者；不为了嵌入库创建第二套文档真相，也不因未来自举就立即重写 Typst。
原对话中关于库嵌入、增量布局和跨平台的判断是待验证输入；Typst 实际 API、字体、资源访问及 license/发行条件由选型调研核定。Auto→JS/C 并不自动保证完整排版库可以运行在浏览器/MCU。

## 2. 实现候选

先用独立 Rust 库/服务驱动探针；有跨语言或动态装载需求时再加窄的 C ABI/AutoABI adapter。复杂文档对象保持原方所有，以版本化 handle/请求/结果与资源服务暴露必要能力，不逐字段照搬全部 Rust 内部类型。
建立 AutoDown block/source locator→排版元素→页/区域映射；区分模型更新、layout、绘制与导出。字体/图片/文档修订、后端版本、配置和 target 进入 cache 身份；编辑后不得显示旧布局冒充当前结果。

## 3. v0.6 候选目标与验收

目标为调研结论＋独立技术原型；是否追加编辑器展示 demo，等待独立探针与 UI 接缝成立后选择。

1. 固定库/字体版本、一个包含标题/正文/公式/表格/图片及分页的文档，产出可阅读页面/PDF，与人工清单逐项核对；不支持的块明确列出。
2. 在同一文档修改一个字和一个跨页内容，记录冷启动、热更新、失效范围、耗时与内存；确认只使用新修订结果。是否增量及收益用观测证明，不以“可重复调用”代替。
3. 缺字体/图片、非法表达式、取消/超时和关闭文档有明确结果；多个文档的资源/缓存隔离，释放可观察。
4. 同一输入重复输出保持约定内容/布局一致；导出产物与屏幕预览的核对项目分开，文件哈希不作为所有布局正确性的唯一标准。

实施 Plan 固定文档规模和可接受延迟/内存/渲染差异，再执行；本稿不预设亚秒保证或整页像素复刻承诺。

## 4. 依赖与拆分边界

独立排版探针依赖 AutoDown 的稳定公开模型及选定排版库，不依赖 AutoUI、AutoMan、AAC 或新 AV。真实编辑器的布局嵌入、选区/光标映射与热更新消费 UI adapter；脚本内容执行消费语言 runtime，不能作为隐含排版权限。
包资源与发行依赖 auto-man/资源 bundle 合同；未来 native 动态库接 ABI 路线。只读参考外仓文档，不在本轮改 AutoDown 实现或生成 Rust 文件。完整 Auto 重写、编辑器全整合和任意 target 支持留后续。
