# AutoHIR：先确定语义，再映射 Atom Schema

> 状态：第一版语义 Draft，2026-10-04。用户提出先提交 Atom/Schema，再确定 HIR，随后用 HIR 验证 Atom。
> Atom/Schema 讨论快照已提交至 v0.6-dev：`63bdaa4af`；提交不是格式冻结。
> 本稿提出职责与核心契约供讨论，不声明 HIR 已实现/稳定，不分配正式 Plan/Schema 编号。
> 关联：[v0.6 roadmap](../../roadmap-v0.6.md)、[Atom/Batom](atom-batom-v2-design.md)、[Schema DSL](atom-schema-dsl-design.md)。
> 第一批具体表达见 [AutoHIR Atom 文本映射](auto-hir-atom-text.md)，含函数/控制流/求值顺序的完整设计样例。

## 1. 当前 Atom 是否足够

从表达能力看，候选 Atom 已有 HIR 所需的结构基础：

| HIR 需求 | Atom 已规划的承载能力 |
|---|---|
| 模块、声明、函数、表达式、块 | Node/Record 与有类型的 Variant |
| 参数、语句、字段初始化、内容顺序 | Array / Node content |
| 操作符、类型种类、控制流分支 | 有身份的 enum/Variant |
| 符号、类型、递归调用、共享常量 | 类型化 ID 表与显式 LocalRef/Link |
| 字符串、数值、静态字节等常量 | 明确宽度的标量、Bytes、TypedArray |
| 诊断位置、扩展元数据、版本 | Record、可选来源 sidecar、Schema 身份/扩展 |

这说明可以开始 HIR 设计，不证明任意编译器语义已经被表达正确。
Atom Schema 可以验证字段/引用形状，不能代替编译器的类型、作用域、控制流和所有权验证。
暂不需要先冻结 Batom tag、cell 大小、索引阈值或完整继承。

## 2. 三份契约分别形成

```text
HIR 语义契约：有哪些概念、哪些程序有效、顺序和行为是什么
    → HIR 数据契约：类型化节点、表、引用、版本、Atom Schema 映射
    → 实现/存储契约：Rust/Auto 内存视图、Batom、后端 lowering
```

先用语义样例和概念类型确定第一份，再用同一批样例设计 Schema；往返检查暴露缺口后
修订 Atom。首个小闭环通过后稳定核心，复杂能力按版本继续演进，不追求一次设计永远冻结。
不能先拼 Node 树，再凭它看起来像 AST 就称为 HIR。

## 3. 层级与前后端边界

建议公共 AutoHIR 保持有类型的结构化高层表示：保留函数、结构化分支/循环、领域操作、
类型/泛型/接口信息和已解析引用。它不是 ABC，也不是只为 native 定制的低层指令列表。

```text
源码 / AST
    → 名称解析、类型推导/检查、语义分析
    → Checked AutoHIR
        → native 专属 lowering / 运行时 ABI / 布局 / 链接
        → A2X 专属 lowering / 宿主语言表示与互操作
        → VM CodeGen / ABC
```

前端可以内部保留未完成推导的工作状态；交给后端的 Checked AutoHIR 必须有明确能力 profile，
不能把 Error/Unknown 类型或未解析名字当作成功。显式 Dynamic/Any 类型如语言确有需求，
应与“推导失败所以 Unknown”分开，并对应明确的运行时操作。

控制流图、寄存器/栈位置、SSA 等低层细节由需要它们的后端阶段决定；公共 HIR 的
信息能否保留应由 A2X/VM 小探针核查，不能等 native 全部完成后再补。

## 4. 核心模块与引用身份

概念模块包含模块/导入身份、声明表、语言类型表、常量表、函数体和源码来源表。
这是职责草图，不是强制每个模块复制一份全程序类型池。

| 身份 | 指向什么 | 与什么区分 |
|---|---|---|
| ModuleId / PackageIdentity | 模块与已解析依赖 | 本机绝对目录不是公共身份 |
| DefId | 函数、类型、全局定义、接口成员等声明 | 显示名称不是唯一身份 |
| HirTypeId | Auto 语言类型 | 不等于 Atom Schema 的 SchemaTypeId |
| BodyId / ExprId / BlockId | 函数体内结构 | 不等于 VM 地址/机器码地址 |
| LocalId / LoopId | 局部绑定与控制流目标 | 按 owner body 限定，不能跨函数误用 |
| ConstId | 可共享常量 | 不等于表达式的执行结果缓存 |
| SourceId / SpanId | 版本化源文件与区间 | 不等于临时内存中的字符指针 |

内部 arena 编号可用于快速访问；导出时重映射为模块/文档内编号。
跨模块引用显式带模块/包身份，不序列化指针，也不把同一个名字误认为同一声明。
Atom LocalRef 只是承载方式；HIR 仍要校验引用目标的类别和 owner。

表达式节点表示一次求值位置。不能复用同一个有副作用的 ExprId，就意外共享/重复执行其结果；
共享类型、常量或声明使用独立表。递归函数用 DefId 引用，不递归嵌入整个被调用函数体。

## 5. 初版核心概念候选

下面是完整语言设计的入口分类，不表示 native 首个探针一次支持全部：

- 声明：函数/方法、全局/常量、数据类型、枚举/带载荷分支、接口及实现、外部声明。
- 类型：标量、值语义 Record、Enum/Variant、Tuple、数组/切片/集合、函数、引用/指针、
  泛型参数/实例与约束、显式动态类型和外部类型身份。
- 表达式：常量、定义/局部读取、明确的运算/转换、调用、构造、字段/下标访问、
  条件/块结果、受支持的借用/移动/写入及领域操作。
- 语句/控制流：局部声明、按序执行、写入、if/match、循环、带目标的 break/continue、return；
  错误传播、清理与异常策略在确定语言行为后正式加入。
- 方言/互操作：UI/AutoDown 等受控扩展操作与已解析外部接口；不能仅留下可执行源码字符串。

运算种类使用明确的 enum，常量带语言类型。`Add` 不应只剩字符串 "+"，
然后由每个后端重新猜是数值加法、文本拼接还是重载调用。

已有语言的 int/uint/usize、字符、字符串类型需分别核对语义，不能在原型里临时认定
它们等于某个 C/Rust 宽度。首个探针可直接选明确的 i32/bool 子集，但这不是裁定整个语言。
整数溢出、转换、浮点与动态运算策略必须进入语言契约和编译配置，不由宿主默认行为决定。

## 6. 求值顺序与控制流不变量

公共 HIR 应明确规定，并由所有后端保持：

1. 块中的执行顺序是显式序列；字段集合本身不是执行序列。
2. 调用参数的源码求值顺序与最终形参绑定分别记录，命名参数重排不能重排副作用。
3. Record/Node 的属性初始化先按规定顺序求值，再形成字段值；不能通过排序 fields 执行初始化。
4. 短路逻辑、条件与循环不能退化为会提前求值所有分支的普通调用。
5. break/continue 指向确定的 LoopId；return 属于确定的函数体和返回类型。
6. lvalue/place 与 rvalue 区分，读字段、写字段、取引用、移动值不能合并成一个含糊的 access。
7. 源码位置可追溯，显式/合成节点分别携带来源与生成关系；保留诊断所需的扩展链。

控制流中的“必定返回”“局部变量已初始化”“退出时清理”等由相应分析保证。
结构化 HIR 中不能未经定义就照搬低层图的支配规则；分析结果需按阶段标记并受校验。

## 7. 类型、所有权与互操作边界

不能只为节点添加 type 字段就宣称完成语义 HIR：

- Record 值语义、共享/引用对象、Linear/move-only、借用和可变性需有明确区分。
- 方法/接口调用的目标、receiver 传递模式、泛型/约束解析结果不能靠名称重新猜测。
- 泛型高层模板可以保留；native 是否/何时单态化是明确的阶段选择，不能提前删除 A2X 所需信息。
- HIR 的引用描述是语言概念；Atom LocalRef 是编译数据引用；两者不是运行时同一个指针。
- C/Rust/Python 等外部符号保留语言/模块/类型身份、调用/所有权契约；链接名称和目标布局由
  具体后端明确生成，不能把 Rust 类型短名当成所有平台都支持的本地数据布局。

首个 profile 可以不支持复杂借用/泛型/外部调用，但必须列出缺项并拒绝，不能降成 Unknown。
完整 AAC 自举范围需另有编译器主体的能力清单，不能拿小 profile 的通过代替自举就绪。

## 8. 方言、属性与后端能力

扩展必须有命名空间、版本、操作定义和语义接口；Schema 有效不等于任意后端可执行。
每个后端声明支持的核心 profile、扩展、运行时/互操作 ABI 与必要 lowering。
语义相关的未知扩展不能静默忽略；可保留为数据，不可假装成功生成程序。

现有宿主属性、宏和原始宿主片段需分类：哪些是通用语义，哪些只能由特定 A2X 消费。
不能假设把它们塞进 Opaque 就能实现 native，也不能为了通用 HIR 把它们从转译结果丢掉。
首个设计/探针必须有“不支持”的诊断路径，而不是未实现分支空输出。

## 9. HIR 校验器与 Atom Schema 的分工

| 层 | 校验 |
|---|---|
| Atom reader | 编码边界、类型 tag、引用/长度、UTF-8、资源限制 |
| HIR Schema | 必要字段、类型形状、enum/variant、结构基数、字段编号、引用描述 |
| HIR verifier | Def/Type/Local 目标与 owner、类型一致性、调用绑定、作用域/控制流、阶段要求 |
| 后端 capability 检查 | profile、扩展、运行时操作、目标 ABI/链接与不支持的语言能力 |

默认不相信来自文件的“checked”标记；重新执行适用的验证，才形成可供后端使用的句柄。
源码 Span 保存 SourceId、UTF-8 byte range 与源版本身份；运行时诊断能定位原始源码，
但用于保存缓存的 source map 是否嵌入文本可另选择，不强迫每个 IR 包携带完整源文件。

## 10. 用样例确定 HIR，而不是先冻结编码

建议先用新建样例覆盖以下语义，再编写对应的 Atom Schema/序列化：

1. 显式类型的函数、两个参数、局部绑定、运算和 return。
2. 嵌套调用与带副作用的命名参数，区分求值顺序和形参位置。
3. if/短路、循环与带目标 break/continue；错误返回类型/越域 LocalId 的拒绝。
4. 值语义结构体/enum/字段访问，以及两个同名但不同作用域的定义。
5. 递归调用、共享常量和跨模块定义引用，不形成递归复制树。
6. 泛型/接口、所有权或动态值中的代表性例子，明确哪个 profile 支持。
7. 一个方言/外部接口例子，验证特定后端支持、其他后端显式拒绝。

语义样例先用概念类型/类型化结构描述；映射阶段再赋予 SchemaTypeId/FieldId/VariantId。
同一套有效/非法样例应贯穿 verifier、Atom/Batom 往返、native 与 A2X/VM 小探针。
判断相等按约定的语义图与来源信息，不按偶然的 arena 编号或排版；引用重映射不能改绑定。

## 11. 近期顺序与待定事项

1. 讨论确定公共 HIR 的层级、核心概念、求值顺序和 ID/来源契约。
2. 为自举所需完整能力建立清单；同时挑选一个小而真实的独立验证 profile。
3. 编写 HIR Schema 和 typed 原型/校验器，做 Atom 表达与往返，用缺口修订 Atom。
4. native lowering/执行探针与 A2X/VM 表达探针，证实公共表示没有偏向一个后端。
5. 冻结验证过的核心 v1 与 Batom 约定域；完整 v0.5 恢复后再做旧前端 adapter 和生产迁移。

本稿未裁定：完整所有权/借用语义、动态值运行时、泛型/接口的具体实现阶段、
异常与清理模型、native 后端库/物理 ABI，以及 AAC 主体所需完整语言子集。
首个平台已由 [Native ABI RFC](auto-native-abi-rfc.md) 明确为 Windows 11 x86-64；
子集与目标代码的分期建议见 [AC 子集与目标代码](auto-ac-subset-and-target.md)。
这些应在相应 profile 执行前解决，不能被“Atom 足够表达”掩盖。
“先定 HIR”是先稳定这组语义边界，再由小闭环验证；不是一次性承诺全部细节永不修改。

## 12. 已核对的本地资料

- `crates/auto-lang/src/ast.rs` 已含核心、UI、扩展等多类语法，ToNode/AtomWriter 是 AST 表达，
  不是已完成名称/类型解析的公共 HIR。
- `ast/types.rs` 包含值类型、集合、引用/指针、泛型、Linear、Option/Result、外部 Rust 类型等。
- `ast/fun.rs` 保存方法/泛型、来源以及宿主/导出属性，迁移时不能只拷贝函数名和 body。
- `types.rs`、`resolver.rs`、`typeck.rs` 为现有类型/模块/参数语义的部分入口，
  本稿没有宣称它们已提供独立完整语义前端。

这些是可见 v0.5 基线的调查输入，主电脑未 push 的计划 739/740 仍可能改变接入细节。
本稿不修改这些路径；正式实现按设计/Plan/worktree 流程推进。
