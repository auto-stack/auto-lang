## 1. 定位与现状边界

统一的是知识数据、来源与引用能力；Jade 的个人知识和 Musk 的项目知识是不同 scope 的消费者，不要求合并应用或仓库。现有 AutoDown 块模型、序列化、编辑器与 Jade 链接索引应先核查复用；旧 Wiki 路线图中的待办不直接当作今日未实现清单。

AutoLens 负责采集入口和上下文，知识核心负责整理/存储/检索，阅读助手提供伴读与注释，学习流程根据作品目标组织知识。图谱、全文、向量检索是可比较的能力组合，不预先要求全部部署，也不因有图链接就宣布无需其他检索。
本轮只引用机器人视觉论文作为可能的静态文档素材，不开展机器人算法复现、模型训练或部署。

## 2. 数据与架构建议

原文/资产不可变保存并带来源、版本与内容指纹；提取的段落、公式、图表保存回链。AI 解释、人工笔记、原文分别标识，保留提取失败/低置信区域，不以重写后的文字冒充原文。

locator 需包含文档修订与结构位置，必要时以引文/区域辅助恢复；更新原文后只能确认重定位或显式标记失效，不能静默把注释挂到错误段落。抽取质量、排版相似度与阅读交互分别验收。

个人/项目 scope 可以引用同一份版本化资料，本地笔记独立可变；权限、删除与分享范围明确。知识包最终复用 AutoMan 身份/依赖体系，不在核心新造 registry、pac 解析器或安装器。索引可重建，原文和笔记必须可导出。

## 3. v0.6 候选阶段与验收

| 子线 | 候选终点 | 验收 |
|---|---|---|
| 论文导入 | 技术原型 | 固定至少一份含段落/公式/图表的可使用 PDF，输出 AutoDown/资产及来源映射；逐项对照人工清单，记录缺失、公式误识别和阅读顺序，不把成功生成文件等同准确复刻 |
| 注释与查询 | 可展示的小闭环 | 为一个段落和一个图表建注释，退出/重开保持；查询或 AI 回答能回到确切来源；原文变更后验证一个正确重定位和一个明确失效反例；模型不可用时原文/笔记仍可读写 |
| Jade/Musk 共同底座 | 数据/接口原型 | 同一资料由个人和项目 scope 引用，更新共享资料保留各自笔记；权限外资料查询失败；先用独立客户端验证，再决定真实应用 adapter |
| 学习与作品驱动 | 调研＋工作流原型 | 固定一个作品目标，展示能力缺口→关联知识→一次练习/quiz→反馈后调整；记录推荐依据和来源。记忆曲线是辅助手段，不把重复答题当系统目标 |
| 共享伴读/社区 | 需求与边界调研 | 定义来源/笔记身份、可见性、修订与删除/撤回；本版不默认交付在线社区或完整协作服务 |

实施 Plan 选择一个完整流程，固定样本、人工 oracle、检索相关性评价、AI 成本/等待与抽取耗时预算；比较基础全文/链接检索与新增图/向量方案的实际收益，不能只展示挑中的成功答案。

## 4. 依赖、拆分边界与下一步

独立 ingest、locator、存储、索引、导出和离线学习流程不依赖三仓拆分完成，可用当前稳定 AutoDown 和 AI 服务接口。使用 Auto 脚本时锁定工具链/资源来源，原型核心不依赖 VM Value、UI 私有节点或 AutoMan Builder。

活体 AutoLens 采集依赖 DevTools/系统平台 adapter；Jade/Musk 界面依赖 AutoUI，知识包安装依赖 AutoMan，跨应用任务依赖通信框架，排版整合消费 Typst 路线。先验核心，接线时再验证真实应用，不能把文件导出/import 称为已共享活体对象。

下一步待选择首条独立路线后，决定先做论文闭环还是通用 ingest/索引，核对 AutoDown/Jade 当前块 ID 与编辑器供料合同。完整知识 OS、协作社区、自动全量采集和个人服务产品化不作为本稿新增的 v0.6 门禁。
