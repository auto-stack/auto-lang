## 0. 定性：从"寄生"到"自主"的分水岭

现阶段 Auto 以源码级转译（a2r/a2c）寄生在 Rust/C 生态上——这是**短期务实选择，不是终局**。
Native 直发（直接产出原生可执行文件）是远期**必做**项，四条理由：

- **a. 系统语言的资格**：缺乏原生二进制生成能力，无法自称系统语言。
- **b. 全链路优化空间**：Auto AST → 机器码的全链路编译器能实施转译路线永远拿不到的
  优化（跨语言边界的内联、整体逃逸分析、语义级优化、寄存器分配全局性）。
- **c. 独立生态**：Auto 现在寄生在别的生态（Rust/Python 等）上，终局需要自己的独立
  生态（AI·Lang·OS）。
- **d. 自有硬件**：未来自研硬件一旦选定架构方向（如 RISC-V），可基于它构建全链路
  Auto 自主生态。

## 1. 路线选项（届时战略级分析的输入）

### CPU

| 选项 | 代表 | 优势 | 风险/代价 |
|---|---|---|---|
| LLVM | Swift/Rust 等 | 目标矩阵免费、优化成熟、生态最全 | 重依赖（体量/编译时/治理） |
| 自研 emitter | Go/Zig 路线 | 全链路自主、编译快、行为可控 | 工程量极大、优化成熟度是长跑 |
| Cranelift | Wasmtime 系 | Rust 生态内、编译快、体量适中 | 优化上限低于 LLVM、定位偏 JIT |
| MIR | 轻量 C 编译器 | 极小、可嵌入 | 社区小、长期维护风险 |

### GPU/NPU（Triton/TileLang 模式）

把 Auto 做成 GPU/NPU 的**原生语言**：张量类型/comptime 设施是天然抓手；与 Python 轨的
PyTorch 消费形成"调用面 → 自主发射面"的演进闭环（先消费 Triton 生态学语义，后自主发射）。

## 2. 与现阶段的关系与触发条件（建议，待细化）

- **a2c 不因 native 而废弃**：C 发射仍是嵌入式/内核等消费面的发布形态；native 是新增的
  自主执行底座，两者并存。
- **产业锚点（2026-09-06 补）：半导体自主化**——native 线是三大市场需求侧的供给侧对应
  面（portfolio"需求侧 3 + 供给侧 1"结构）：GPU/NPU 语言面（Triton/TileLang 模式）切入
  AI 芯片软件栈（半导体增长最快的段，同时在 AI 市场内）；HLS（C→RTL）是远期连续路线
  （comptime + 动静结合映射"算法级仿真→HLS/RTL 发射"）；与自有硬件/RISC-V 倾向（理由 d）
  构成完整产业叙事。
- **主战场先行**：届时锁定 1–2 个硬件架构方向（如 RISC-V/Arm）做全链路打通，不铺开矩阵。
- 触发条件建议：① 自举收口（GOAL-017）② 一个需要 native 的主战场成立（自有硬件立项 /
  性能临界的旗舰应用）。
