## 1. 结论

1. 新 Atom/BAtom 的数据模型、编解码、兼容性语料与基准原型。

   详见 [应用独立化草案](demo-app-independence-strategy.md)。

主要工作集中在 auto-lang 的 v0.6 新目录，相关消费仓先冻结为只读基线。

等主电脑内容恢复后再实施。现在可做这些方向的调查、语料和独立接口实验。

按计划 739/740 的最新信息进一步收紧：新增文件也不能成为续做既有工作的理由。

第一批代码优先独立定义模型、输入格式和实验 CLI，以语料/接口契约连接未来生产路径。

选择标准是未来适配成本、可验证成果与 v0.6 关键路径价值，不能只看是否新建文件。

## 4. 近期任务建议：可交付代码且适合未来合并

建议使用新增的 `experimental/v0.6/`，下述 crate/目录名均是候选，不是已创建内容。
实验内部可用独立 Cargo workspace、锁文件与 target 命名空间，减少根 Cargo.toml、
Cargo.lock 和共享输出的改动。正式接入时再按拆仓设计确定最终归属。

### B1 Atom/BAtom 契约与编解码原型（首选）

2026-10-04 用户需求与模型/格式候选见 [Atom/Batom v2 设计草案](atom-batom-v2-design.md)。
先讨论独立内存、Schema/struct 映射、Node/Lisp 与 D/S 编码，不替换现有 Value/Atom。

现状有三个不同层次：

- auto-lang/crates/auto-atom：Node/Obj/Array/Empty 的标记树，底层依赖 auto-val。
- AST 已有 ToNode/ToAtom/AtomWriter 序列化；它不是语义分析后的 HIR。
- auto-shell/ash-core 的 Atom：Value + 管道 AtomType；Batom v1 是管道二进制格式。

Shell Batom 的 `encode_value` 对 Node 等不支持值直接写 TAG_NIL（约 543 行），
不返回 Unsupported 错误；不能直接拿它承载编译器树并声称往返无损。
本次只读发现，不在旧 Shell 上顺手修补。

任务：设计区分持久数据/编译器数据与运行时句柄的模型；实现新原型的 Node、字段、
子节点、标量、引用与二进制往返。定义文档格式版本/Schema 版本、数字宽度、字段与
子节点顺序、未知标签和错误行为。运行时闭包/指针等明确拒绝或引用化，不静默变 Nil。

验收：AST/知识实体/包清单三类真实结构样本；文本与二进制语义往返；无效/截断输入
确定性报错；重复编码可复现；尺寸、时间、分配基准。文本“语义往返”不自动包含注释
与原始排版逐字节保留，须另行决定。暂不替换 auto-atom/auto-val/Shell Batom 现有 API。

### B2 HIR 最小实现与校验器（与 B1 互相验证）

Rust 实现函数、参数、局部绑定、整型/bool、运算、调用、if/循环/return 等小范围 HIR；
包含 SymbolId/TypeId、源码位置、模块身份与诊断。先定义类型化表示，再提供 Atom
可读视图和 BAtom 持久化，避免每个 pass 先拼动态对象。

校验器核查引用闭合、类型/调用参数、作用域和控制流，具体规则按所选 HIR 层级确定。
同一 HIR 原型同时保留高级结构，并用独立 native lowering 转向低层表示，避免一开始
把共享 HIR 固化为只适合机器码的指令集合。版本化 ID 不携带当前进程的地址。

验收：有效/无效语料、规范化 dump、保存/读取后的校验、错误源码定位；未来 A2X/VM
各挑一组信息需求做设计核查。现在不实施这两个后端的正式迁移。

### B3 Rust AC 的首个真实 native 闭环（首选代码主线）

首个实验平台可暂定本机 Windows x86_64，Linux target 与可复用后端接口纳入设计；
这不是冻结 v0.6 平台范围。后端选择用小探针比较，不从 fork rustc 或全 ISA 自研开始。

本机 Rust/Cargo 可用；当前 PATH 与常见 LLVM 路径未找到 clang/lld/llvm-config，
抽查 Cargo registry 也没有 Cranelift/llvm-sys/inkwell 缓存。后端依赖获取、链接器定位
与最小产物验证应作为独立前置任务；已装 Linux rust-std 不代表已具备 Linux 运行验收环境。

10-04 VM 构建补充：Rust MSVC 工具链及配置中的 rust-lld.exe 已实际完成链接。
上述 PATH 调查不能读成“本机没有任何可用链接器”；native 实验仍需验证其目标文件/ABI。

分两个阶段，近期只执行第一阶段的独立实验：

1. 手工构造的有效 HIR → native lowering → 目标文件/链接/本机执行，验证真正后端。
2. **完整 v0.5 基线恢复后的接入阶段**：复用现有前端的薄 adapter → 小子集名称/类型处理 → 同一 HIR → native 执行。
   adapter 只消费支持的语法，不修改旧 parser/VM；未知或未支持语义明确拒绝。

第二步完成才称为 Auto 源程序的最小 AC 闭环。只有 HIR→native 时如实标注后端探针。
不通过 a2r/a2c 绕行后将结果冒称 native CodeGen；使用外部链接器/后端库则明确记录依赖。

近期验收包括 HIR 函数调用、分支、循环/递归、校验诊断、ABI 边界与独立生成制品可运行；
使用预期行为明确的独立语料，不为对拍修改旧 AVM/a2r。源码 adapter 和生产后端对拍
在完整基线恢复后安排。第一批不承担 UI、完整 stdlib、GC/动态对象、
全部 Rust 互操作、优化器或 AAC 自举。成果是向自举推进的真实基础，不宣称已自举。

### B4 Package/Install 核心原型（独立于编译器，可另线推进）

不改现有 auto-man build/resolver 或 auto CLI；实验独立实现：

- 四实体类型与 build/runtime/content 依赖边、包 ID、版本锁定；用户数据所有权和
  知识引用单独建模，不能全部变成安装依赖。
- 内容寻址存储、安装 profile/代际、引用根与可回收对象。
- 本地文件源的真实安装/更新/卸载；阶段化执行与失败/重启恢复。
- 同依赖复用、版本并存、取消/并发、升级迁移失败时的数据保留。

所有状态/文件只写临时实验根，应用和用户数据使用独立 fixture。明确“本地源已验收”，
不将未实现的远端下载、Launcher、全部平台 adapter 计入结果。原型可提供独立 lab CLI，
正式 auto CLI/Launcher 接入等完整 v0.5 和 auto-man 拆仓边界确定后实施。

有实际磁盘操作与故障恢复证据后，核心可迁入未来独立 auto-man 仓；不要在 1 月旧仓
开始实现，再将整套旧依赖一并复活。

互操作或继续自举展示来替代近期的新方向开发。

## 5. 为什么暂缓拆仓和直接产品演进

拆仓涉及移动/删除、路径依赖、CLI、feature、Schema、公共 API 与多个消费仓。
auto-man 当前还显式依赖 auto-lang/ui-iced；auto-shell、Musk 通过相对 path 引用
auto-lang/auto-val/auto-ai；auto-lang 的 autodown 可选依赖也引用兄弟 auto-down。
这不是简单 rename 合并，隐藏修改很容易导致文件回流、漏迁移或混合版本构建成功
但运行语义不一致。工作区依赖即使 feature 关闭也不能未经验证假设不需解析 path。

因此暂停：三仓物理拆分、全 Rust 重构、公共 Atom/Value 替换、旧 AST→VM/A2X 接线、
Launcher 安装按钮、Musk/Jade 新知识格式、共享 target/测试治理重写。
它们的只读调查、设计和独立原型可以继续。
根据用户补充，28-app 独立化从暂停清单移出：新增产品仓与 submodule 可先行；
四大主力 app 不动，媒体改进与已有 OS 目录替换按单项来源/冲突证据安排。
