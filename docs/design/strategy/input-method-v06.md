# AutoInput / AutoIME：v0.6 调研与独立原型

> 2026-10-21 版本范围更新：按[月度滚动规划](../../roadmap.md)，v0.6 仅保留工程重构、ACE、AutoGraphics/Forge 雏形与 Linux 四条主线。本文下方旧 v0.6/v0.7 版次和日历按历史排期读取；其余目标进入[远期 TODO](../../roadmap-future.md)，不自动承诺 v0.7 全部交付。技术合同与已批准在途 Plan 的范围/验收保持，四线所需局部能力随所属主线验收。

> 2026-10-16；目标态草案，名称与协议尚未冻结；本轮不实施。来源为 AutoOS《设计跨平台输入法》，系统集成关联[平台阶段设计](platforms-v06.md)。

## 1. 长期目标与复用

统一输入引擎和文本交互语义，分别适配 Windows 与 Linux；长期允许与 AutoUI、Shell、compositor 深度融合。初期评估复用 Rime 等引擎及已有系统框架；不在没有实测时宣布替换 TSF、Fcitx/IBus 或重写 Linux 输入栈。
当前只有讨论依据，本轮未验证可用的 AutoIME 产品、引擎 binding 或平台兼容性；实施前盘点已有 AutoUI 文本/IME 路径，避免再写一套状态。

## 2. 架构与责任

区分输入引擎（按键/上下文→组合/候选/提交）、会话协议、平台 adapter、候选窗和编辑器文本状态。组合文本、已提交文本、选区、周边文本的所有者分别明确，候选对象不持有失效的 editor 指针。
会话/焦点带 generation；切换输入目标后旧事件不得写入新目标。明确按键消费、取消、提交、光标区域、DPI/坐标、密码输入限制、服务断开与重连行为。候选窗的定位/渲染属于宿主适配，不放进词典与排序核心。

## 3. v0.6 候选目标与验收

| 阶段 | 成果 | 验收 |
|---|---|---|
| 调研 | Windows/Linux 接入路径、引擎复用与能力矩阵 | 固定 OS/会话/工具链，列出已有框架可用能力、缺口和自研代价；候选方案有可重复的探针或明确阻断 |
| 独立原型 | 一个引擎＋一个平台的独立测试宿主 | 输入、候选翻页、选择/提交、取消和退格完整；两编辑目标间切焦点，旧组合不能串入；退出重开配置保持；离线与引擎错误有确定行为 |
| AutoUI 接入 | 后续条件阶段 | 在真实文本组件验证选区、中文/英文混输、光标/DPI、多窗口和失焦；独立测试宿主通过不等于此阶段通过 |

首个 Plan 根据环境选择一个平台，不把 Windows/Linux 双平台成熟产品同时列为原型门槛；记录组合更新/候选响应延迟和资源预算，阈值由选定负载确定。

## 4. 依赖、拆分与后续

引擎、词典、会话状态机和独立平台宿主可不等拆分。接入 AutoUI editor、native provider、窗口输入与 Linux compositor 时需服从 Design37 的所有权与当前接口；共享服务接系统通信，不另造全局应用总线。
原型使用清楚的小接口/事件记录，不新增 core AST/Value 变体，也不借此改全 UI 事件管线。完整自研 Linux 输入法框架、跨设备输入与多平台产品化留后续；独立原型结果用于决定复用和自研比例。
