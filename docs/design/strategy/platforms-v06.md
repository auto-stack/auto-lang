## 1. 分期与验收

| 路线 | v0.6 目标 | 可验收标准 |
|---|---|---|
| Linux | 已确认主打交付；先固定首个发行版/硬件/桌面会话支持集 | 从干净系统安装/进入会话，运行约定四大 app 与28项应用矩阵；窗口/焦点/输入/剪贴板/文件与服务、安装升级/退出恢复均有真实流程与反例。明确 GPU/显示服务器、字体/DPI、外部应用接入和未支持设备，不能凭一个 Linux 窗口宣称全支持 |
| 鸿蒙 | 已确认最低目标：虚拟桌面与28个 demo 正常运行 | 固定 OS/API/设备与完整应用清单，每项启动、布局、交互/状态、导航和必要服务取证；独立重启/构建可复现。先 rebaseline 现有 a2ark，再补当前契约；一个 HelloWorld 不替代矩阵 |
| Web/Windows | 保持既有能力，验证拆分后的消费兼容 | 用锁定版本的外部消费者覆盖实际构建/运行、资源、典型交互及独立 app；Windows 发行不要求先运行完整虚拟桌面 |
| Android/iOS、MCU/LVGL | 后续候选；v0.6 可留调研记录 | 记录工具链/平台缺口与重启条件；不自动立新生成器或许诺平台交付。保留现有 Compose/ArkTS 路线，不以本稿重新选型 |

“全支持”必须落到有限且公开的支持矩阵；上述验收细目是建议，首个 Plan 还需冻结设备、用例、失败分类和测量阈值。未达项明确记为未完成，既有目标不能默默换成调研结论。

## 2. 可独立准备与集成依赖

Linux 环境/镜像制作、系统服务/窗口/输入 API、鸿蒙官方 SDK 与独立原生示例可先调查和探针；它们只证明平台环境。库/SDK/设备选型需要实际环境验证，本次未重新查询其当前版本。

真实桌面会话、AutoUI renderer、a2ark/a2jet、宿主 native、UI 工程构建与资源发行均与拆分重叠：语言层只消费 SDK，UI 拥有 backend/provider，AutoMan 负责编排和安装。不得在现有 compiler 中再加入平台 UI 关键字或依赖 renderer。
Linux 输入法深度融合消费[输入法路线](input-method-v06.md)，系统服务消费[通信路线](system-foundations-v06.md)，安装消费[统一核心](unified-package-install-strategy.md)。各自独立原型不能替代最终平台组合验收。

## 3. 后续决策

路线选择后确定首验环境和容量；已有“未同步主机”描述视为历史基线限制，需重核当前源码/设备组合，不假设至今仍缺失。本稿不代替所属仓的发行计划、签名/设备测试或兼容性收据，也不重排已批准在途 Plan。
