## 1. 分期与验收

| 路线 | 当前版本归属 | 可验收标准 |
|---|---|---|
| Linux | v0.6 交付首个支持范围明确的发行预览；工程重构完成、RQHost UI 渲染完善后正式集成/交付 | 固定基础发行版/硬件/桌面会话与代表性应用清单；干净环境安装/启动、窗口/焦点/输入、约定文件/服务集成、升级与退出恢复有真实流程及反例。明确 GPU/显示服务器、字体/DPI、外部应用和未支持设备；系统镜像形态另验镜像安装/启动，仅一个 Linux 窗口不等于发行完成 |
| Linux 扩面 | 远期待选，原全生态与四大 app/28-demo 整体矩阵保留为扩面目标 | 逐发行版/设备/应用扩展并记录实测；不能把首发有限矩阵写成生态全支持 |
| 鸿蒙 | 远期待选，保留虚拟桌面与28-demo 方向 | 冻结 OS/API/设备与应用清单后，逐项启动、布局、交互/状态、导航和必要服务取证；独立重启/构建可复现。先 rebaseline 现有 a2ark；一个 HelloWorld 不替代矩阵 |
| Web/Windows | 保持既有能力，验证拆分后的消费兼容 | 用锁定版本的外部消费者覆盖实际构建/运行、资源、典型交互及独立 app；Windows 发行不要求先运行完整虚拟桌面 |
| Android/iOS/macOS、MCU/LVGL | 远期待选，不预排月份 | 记录工具链/平台缺口与重启条件；不自动立新生成器或许诺平台交付。保留现有 Compose/ArkTS 路线，不以本稿重新选型 |

上述版本重排显式替代 2026-10-16 的 v0.6 范围；技术验收原则保留。首个 Plan 仍需冻结发行形态、设备、应用/用例、失败分类和测量阈值；未达项明确记为未完成，不用调研结论替代约定发行成果。

## 2. 可独立准备与集成依赖

Linux 环境/镜像制作、系统服务/窗口/输入 API、构建与安装流程和验收清单可以提前准备；它们只证明平台环境，不放行正式发行。正式交付前先核实工程拆分及约定 crate 检验/重构清单完成、RQHost 完善；80 万行争取指标单列，不额外等待未来全部深层重写。
RQHost 在 Linux 上验证绘制/裁剪/字体、输入法/焦点/光标、窗口/DPI、资源路径、多应用隔离、连接/断连与退出回收，不用 Windows 结果外推。Linux 不追加“完整 3D 引擎完成”的前置。
其他平台的环境调查按后续版本选择，不因本文保留候选而默认开工。库/SDK/设备选型需实际环境验证，本次未重新查询其当前版本。

真实桌面会话、AutoUI renderer、a2ark/a2jet、宿主 native、UI 工程构建与资源发行均与拆分重叠：语言层只消费 SDK，UI 拥有 backend/provider，AutoMan 负责编排和安装。不得在现有 compiler 中再加入平台 UI 关键字或依赖 renderer。
Linux 所需现有输入法、服务、安装升级切片随主线验收；更完整的[输入法](input-method-v06.md)、[通信](system-foundations-v06.md)与[统一安装](unified-package-install-strategy.md)在远期候选，不要求先交付整套体系。复用现有公开核心和 adapter，各自独立原型不能替代平台组合验收。

## 3. 后续决策

路线选择后确定首验环境和容量；已有“未同步主机”描述视为历史基线限制，需重核当前源码/设备组合，不假设至今仍缺失。本稿不代替所属仓的发行计划、签名/设备测试或兼容性收据，也不重排已批准在途 Plan。
