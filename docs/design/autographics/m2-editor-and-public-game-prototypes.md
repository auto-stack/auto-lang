## 3. 架构边界

```text
独立游戏仓库：Auto玩法、场景/关卡、项目配置、资源引用与许可
    ↓ 公共且版本明确的场景/行为/资源/游戏服务接口
AG独立宿主：编辑会话 / Play会话 / 输入 / 项目与资源 / renderer adapter
    ↓ 现有公开旧AutoVM SDK + 共享wgpu/Iced实验基础
Auto执行玩法与状态；宿主负责受检发布、系统与GPU资源
```

游戏作者不编写transport、不依赖Rust内部Host/测试探针、不修改宿主switch来识别游戏名称。引擎可增加通用服务，但服务的规则和失败行为须由后继Plan独立冻结。游戏规则、敌人决策、计分与重开流程由真实Auto执行，不用Rust替代。

两款样本消费同一份公共接口和相同执行基线；不为2D/3D分别复制VM、资源系统或运行调度。编辑相机与运行相机、编辑内容与运行状态、持久ID与Run内句柄分别建模。沿用M1的失败保留最后完整画面、Stop恢复编辑内容、来源/资源/owner可核查原则。

未来归属采用auto-ui同仓多crate、可选择图形依赖的方向，AG核心保持不反依赖完整组件库。等ACE成熟后再立集成Plan：短期集成分支→分批增量合入→新旧路径共存→兼容验收后切默认→回退窗口后退役旧路径。代码合入、默认切换与旧实现退役分开；本批856–858不执行仓迁或替代旧AutoUI。

已有profile1..11、behavior/1..5、scene4、CPU/资源上限和错误分类作为兼容面保留。新运行拓扑、输入或资源能力若改变语义/限制，使用显式版本和迁移/拒绝规则，由功能Plan在可行性调查后冻结；不得把旧profile静默改成新游戏协议，也不提前许诺无限节点、无界脚本或任意帧率。

### 3.1 桌面、WebGPU与移动端的目标边界

共享场景/运行语义、资源身份、动作/事件与绘制描述，renderer/平台服务隔离。浏览器优先调查Rust图形核心→WASM/wgpu→WebGPU，普通UI用Vue/DOM；移动原生与移动Web各自profile，UI后端不提前钉死。当前不重组crate或承诺旧SDK可编WASM，正式执行环境另验。

Vue→Canvas、DOM overlay、3D表面可采样UI分别协商：任意DOM子树没有可直接当作通用WebGPU纹理的既定路径；overlay不天然参与3D深度/裁剪，可采样UI需要另一个支持子集明确的UI adapter。统一声明语义不等于统一物理渲染树。DOM/GPU跨域只在明确commit/layout/输入合同下认领一致性，不承诺原生同设备式物理原子呈现。

后继Plan应冻结异步资源/请求代次、语义输入与触摸映射、逻辑时钟与后台暂停、device/surface代次/重建、能力分级与受检降级；JS/WASM ID精度和颜色/alpha/坐标规则明确。GPU失效时保留last-good逻辑状态不等于旧帧缓冲仍可见。完整说明、限制与XP-0..5研究出口见[平台专题](platform-architecture-and-research.md)，不追加入874/875验收。

### 3.2 源码归仓与融合门分开讨论

auto-ui已完成独立仓交付；技术上AG可先作为其experimental独立workspace保留旧SDK/锁/入口，不必将纯源码归属与ACE融合绑定。建议874/875实际交付后另立纯搬仓Plan，先核完整清单/来源身份/目标隔离/回归及切权威恢复；生产UI/声明/ACE融合继续原门。此为本轮提出的排期调整候选，不是启动迁移或自动取消此前约束；当前源码权威仍留auto-lang/autographics-dev。证据与步骤见[归仓专题](repository-move-and-integration-gates.md)，878只做准备审计。

## 4. 编辑视口

### 4.1 共同规则

网格/轴/选框/操作手柄是编辑辅助层，不是游戏节点，不参与游戏碰撞与行为tick。编辑相机操作不改变场景内容dirty/Undo历史；如保存工作区观察状态，应使用独立的编辑器状态，不能混入角色或场景变换。网格密度/线数/辅助资源有界，缩放不会无限生成几何；具体上限在视口Plan冻结。

实际呈现的相机、viewport、DPI与对象身份是选择/拖动的共同来源。导航、resize、失焦、Esc、模态操作与Play切换须明确捕获/取消规则；旧相机下的迟到指针或候选不能提交到新视图。进入Play后编辑快捷键不能同时驱动游戏角色。

### 4.2 2D

- 显示原点、坐标轴和可开关网格，主/次网格随缩放调整。
- 鼠标视口平移、围绕明确锚点缩放、聚焦选中对象；不同缩放下拾取/拖动一致。
- 可开关的平移吸附；单位、步长和负坐标/中点规则在Plan写明，关闭时保持自由拖动。
- 2D精灵、图层/遮挡和关卡组织按平台样本所需建设；完整TileMap编辑器不自动纳入。

### 4.3 3D

- 地面网格、原点与X/Y/Z轴；有限透视和正交模式。
- 环绕观察点、平移、缩放/推拉、聚焦选中对象，以及视图重置。
- 导航后仍能准确选择、显示平移手柄与执行吸附；支持的相机/近远平面与退化拒绝范围明确。
- 旋转/缩放gizmo、视图立方体、多选框选、任意曲面UI属于后续可选项；现有属性面板仍能编辑已支持的值。

## 6. 独立工程与资源交付

两个正式游戏放在`auto-lang`和未来引擎仓之外，各自建仓；建议名`ag-platformer-2d`、`ag-platformer-3d`，实际远端/所有者在建仓Plan确定。本轮不建仓。引擎只保留必要最小示例/回归资源及示例索引；既有M1资产和证据不在优化阶段删除或搬迁。

Gallery另外使用轻量`ag-examples`仓（建议名），保存小示例/目录/源码/许可与小资源；两个游戏只被索引，不复制到集合。仓级共享资源按hash管理，单项下载包按支持的项目格式实体化为完整本地闭包，无跨仓路径/链接/cache前置。大资源/录屏/制作源按固定包可选下载，网页初版只做预览和下载索引，原生运行入口明确。目录结构、元数据、资源来源/派生与下载规则见[专题§5](m2-gallery-and-capability-matrix.md#5-仓库目录和资源组织)。

- 示例Git保存Auto源码、场景、配置、许可、资源清单，以及体积合适的必需运行资源。
- 实际盘点后，将大型贴图/音乐/高清包外置；美术制作源文件单独可选下载。资源体积与下载预算以实测清单冻结，不假定所有GLB都很大，也不提前绑定LFS/CDN/包管理产品。
- 每份资源清单绑定资源版本、固定URL或发布资产身份、SHA-256、长度、目标相对路径、来源与许可。下载前显示需要的内容/大小，缺失或不符明确拒绝；不可静默拉latest或退化为占位图冒领验收。
- 外置资源落到工程内成为完整闭包，不依赖生产者绝对路径或仅存在于全局缓存的文件。禁止链接/越界解包，沿用路径与资源准入规则。
- 每款游戏发布一份源码＋运行资源的完整ZIP；拿到包后可离线编辑/运行/搬迁。源码仓＋固定资源包的组合也是受验入口，资源修复后须重新实际启动。
- 示例锁定公共引擎提交/版本及适用平台/profile；游戏与引擎可以独立发布，但M2验收绑定两款游戏、引擎、SDK、资源及配置的完整版本矩阵。
