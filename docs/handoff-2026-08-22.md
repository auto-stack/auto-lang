## 工作规范（沿用既有模式）

- **Worktree 流程**：`git worktree add .worktrees/plan-fix-XXX -b plan-fix/XXX master`
  → 修复+测试 → `git merge --no-ff` 回 master → 删 worktree → 推 origin+gitee 双远端
- **测试命令**：
  - a2r golden：`RUST_MIN_STACK=33554432 cargo test -p auto-lang --lib --features test-trans a2r_tests`（基线 340/340）
  - 全量 lib：`cargo test -p auto-lang --lib`（3048 过，`route::discovery::tests::test_exists` 失败为已知环境项）
  - ui-iced 门控测试：`--features ui-iced`（vm_bridge/dynamic/plan370 等在默认构建不编译）
  - http e2e：`--features test-http-e2e -- --test-threads=1`
  - 实机 desktop_mcp：`cd examples/ui/XXX/tests && AUTO_BIN=<exe> python desktop_mcp.py`
    （已覆盖 011/013/015/038 四例）
- **归档流程**（finish-plan → archive-plan）：代码级复核 → 延期项登记债务簿 → 状态行 ✅ →
  git mv archive/ → 更新 plan-indices/plan-reports → 提交推送
- **跨仓验证环**（a2r 改动必做）：worktree 构建 → auto-ai 三 retranspile + cargo check 零错
- **全绿纪律**：不达标不合并——宁可撤回 worktree 登记发现（P2-B #1 前两轮即此模式）

## 环境陷阱（踩过的坑，重要）

- **python 补丁必须二进制安全**：`open(p,'rb').read().decode()` + `open(p,'wb').write(encode())`
  ——文本模式会重写整个文件的行尾（git diff 爆 12000+ 行）；renderer.rs 是 CRLF，
  layout_collector.rs 是 LF，**多行锚点匹配前先查行尾**
- **Git Bash heredoc 吃转义**：复杂补丁用 Write 工具写 .py 文件再执行
- **CALL_SPEC 实参序**：栈顶是**最后一个**实参（弹参从末参开始）
- **native catalog 编号**：新函数必须全局唯一新号（3108/3109 已占）
- **VM 模式 body 恒为单参数**（整个 JSON 串）——多字段解析走 json_str 提取器（023 api.at）
- **render_support 静态表**须与 aura_view_builder 实际 tag 分支同步（否则 autoui_check 假阳性）
- **已知预存测试失败**（勿误判回归）：lib 的 route::discovery test_exists（环境项）；
  ui-iced 下 plan370 d3/d4/d6/d7 + calendar ×2 + style test_sizing（基线一致）；
  e2e_notes_crud 顺序竞态 + concurrent_sse flake（文档化）
- **auto-ai 有并行会话**（PLAN-030/033）：auto-lang 主 worktree 的
  `examples/rust-workspace/Cargo.toml`（plan-032-back）是并行 WIP，勿动勿提交
- 既有 worktrees（auto-down/auto-edit-dev/auto-edit-ux/auto-shell）是并行会话工作流，勿删
- a2r 套件必须 `RUST_MIN_STACK=33554432`；僵尸 auto.exe 占端口用 AUTOUI_MCP_PORT 免疫
- **主仓 target/debug/auto.exe 可能过期**——跨仓验证前先在 worktree 构建
