## Original content

Design 01 §4-P3/§7 P-3 批（PLAN-586，Category B，主仓 auto-lang）。三步：
① extra roots 兄弟探测泛化——默认探测列表 [../auto-os-config/auto] 扩
[..., ../auto-os/apps]，apps/ 每含 pac.at 的直接子目录=一个 local root
（排序/pac.at 门控/id 去重/缺容器静默；vue 轨 desktop_extra_app_roots 与
vm/iced 轨 app_registry::extra_roots_from+expand_apps_container 双侧同律，
scan_siblings 门控同族受控）；② apps.manifest 框架侧直读聚合（用户裁定
2026-09-07）——resolve_os_manifest_root 解析序（AUTO_OS_ROOT env **设置
即权威不回落**〔兼关断开关〕→兄弟 ../auto-os→主检出 D:/autostack/auto-os
兜底）+ manifest_repo_roots（repo 条目 extra root 原生挂载；local 由容器
展开覆盖；status≠active/未知 kind/坏 JSON/无 pac.at 跳过+警告不炸启动）；
③ iced 轨 DesktopOptions.extra_app_roots（沿 apps_dir 先例，Some=全额替换
=vue 轨 env 同语义，None=host_extra_roots 缺省探测）+ 三轨 parity 锚测试。

【执行期修正（较 Design 01 §4-P3 草案）】repo 条目注册为 **extra root 原生
挂载**而非「经 remote/URL 机制注册为远程窗」——remote-apps.json（Plan 516
G4）实测为 WS 投影协议端点（RemoteAppConfig.url 全 WS，连的是另一桌面
实例投影面），http/原生 app 形态装不进；repo 仓本身即 pac.at+src/front/
app.at 单 app 根（os-config 先例同型，kanban README VM 轨 auto run -r vm
原生跑）。Design 01 §1-C「remote 窗或 extra root」两候选中后者落地；纯
web app iframe 嵌入列 Stage C。

验证：vm 轨 37↔36 entries 差值恰 kanban（desktop-visible 21↔20 同步，
AUTO_OS_ROOT 关断对照）；vue 轨 extra root 注册+api glue 安装（物化受
vue 宿主 v1 单视图预存限制）；tf 2619/2620 唯红=charts 预存（564-Q6）。
§3-a 包装脚本随 P-6（用户裁定）；交互级启动验收归 P-5 V1/V2。
