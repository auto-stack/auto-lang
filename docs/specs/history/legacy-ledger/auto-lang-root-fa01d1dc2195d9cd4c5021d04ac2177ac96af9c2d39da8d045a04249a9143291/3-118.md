## Original content

PLAN-669 修复 VM 模式 #[api] handler 实参装配违反 spec §4.1 的断层（query 集合串/body 原始串按位直塞）。注入规则五条：路径段→body JSON 字段→query 参数按名绑定（声明序，同名 path 优先）；int/float/bool 精确类型转换（parse 失败 400 指名）；缺参→HTTP 400 {"error":"missing param `名`"}（back_proxy Plan 658 对齐）；单参 whole-body 容忍（唯一 str 形参未按名供给时收整个 body 串——Plan 346 单参 body 契约延续，含 multipart 字段 JSON）；元数据形参按名 opt-in（尾随形参名∈{meta,metadata,req,request} 收 {"cookies":...,"auth":...}，其余未供给一律 400）。实现链：codegen 在 api_routes 采集点发布形参签名（名+Type Display）到进程级 API_PARAM_SIGS 侧信道（axum_adapter PARAM_SIGS 同型生命周期，run pipeline 编译前重置）→四条 serve 路径（handle_connection_async/serve_blocking_stdnet/run_http_server_blocking/shim_http_server_listen）统一 bind_api_args_by_name（同步三路径经 bind_api_args_or_legacy，无元数据源——meta 形参 400 指名，差异见 §4.1.1）→无签名条目回退旧位序装配。附带根修：async 请求头单次 read() 遇 TCP 分片产生空 400（plan 568 T7 th 档"环境红"真身），改读至 

。__axum: 合成路由走 axum_adapter extractor 编组、a2r 轨参数绑定在生成代码里，均不经此链。

PLAN-696（2026-09-23）：VM `#[api]` server 按 Content-Length 读满 body，校验非法/重复长度、短体与不支持的 Transfer-Encoding，设置有界大小和读取期限；AutoVM 由同线程 LocalSet/Rc owner 持有，不再跨线程转运 VM 指针；SSE generator 分片让出调度，连接断开后取消 producer。生成 Axum server 是独立路径，a2r-std HTTP 为客户端，`stdlib/auto/http.rs.at` 不存在。支持和限制见 §8.1；Spec SHA-256=84F437D0BF49DE4FD9CAFB1F76629665C9C6AD3757C266F955C5F319FB1C8F30。
