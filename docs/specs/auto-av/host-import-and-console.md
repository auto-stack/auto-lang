# Typed host imports and console (PLAN-863)

The experimental whole-module execution profile is `av.host-console/1`, numeric profile **8**; MIR schema `auto.mir.av-host-console/1`, ABC schema `auto.abc.av-host-console/1`, magic **AVHC**, wire **1**. Its HIR/source domain is host-console. Old AVAD, AVAU and scalar contracts remain separate. Shared HIR→MIR lowering contract is **3**, with AV/CTE/MN parent identity mirrors at 3. The ac/run backend tag reuses the MN admission mirror; stale comparison uses the current per-row backend identity rather than a caller's shared tag.

`MirHostImport` is a separate module table, carrying category, symbol, exact signature, required capability and maximum call bytes. `HostCall` (opcode `0x35`) refers to that table and a typed input slot. It is an effect instruction with no manufactured integer result. Guest/import calls keep their prior semantics. Console function-unit modules are rejected (`mir.host-unit`); this profile introduces no resident/incremental console linker.

Category `console/1` admits `auto.console.print.{i32,bool,str,char}.v1` with `console.stdout`, and `auto.console.eprint.{i32,bool,str,char}.v1` with `console.stderr`. The verifier checks the complete table, including declarations only referenced by unreachable functions. Unknown symbol, category/signature/capability mismatch, duplicate symbol, unauthorized capability and invalid reference have distinct `host.*` diagnostics (`unknown-symbol`, `signature`, `duplicate`, `unauthorized`, `reference`). Host symbols cannot masquerade as guest imports. Admission validates all required grants before guest execution, yielding zero dispatches/output on rejection.

The host supplies the provider and current grants per run; declarations are requirements rather than grants. The native trusted provider interface returns success, resource, cancellation or I/O failure. Generic guest execution without a host provider rejects modules with a nonempty host-import table; profile-8 modules without host imports retain generic execution. A thread-local RAII scope rejects synchronous guest reentry during provider dispatch and clears on return/unwind. This is an in-process trusted host interface with no memory-isolation promise.

Every call appends LF. Limits including LF: **65,536 bytes per call**, **1,048,576 bytes per run combining stdout and stderr**. Output staging and retained bytes count against execution memory (`resource.slot-bytes`); retained capture exceeding the output quota yields `resource.console-output`, taking precedence when both retained-byte limits are exceeded; host work consumes fuel and call depth. Checked reservation precedes allocation/write. The in-memory provider commits a call atomically: an oversized call writes no bytes, returns `resource.console-output`, and preserves earlier calls. Resource, cancellation and infrastructure/I/O outcomes are distinct from guest traps. Cancellation is checked before dispatch/commit; trusted providers cooperate during their work. Already emitted output is not rolled back. Provider I/O failure is infra (`host.io`).

Portable AVHC artifacts contain typed requirements and their fingerprint, never native addresses, handles, provider instances, grant credentials or loaded authorization. Managed-store identity binds owner/entry, source, wire/profile/semantic identities and requirements. Admission checks every encoded function source snapshot against the expected snapshot (`host.identity` on mismatch), before persistence/execution and after restore. Every restore decodes/verifies and every run rechecks current grants; an old artifact cannot retain a withdrawn capability. Profile/header masquerades are rejected in either direction. The native backend explicitly rejects this profile; no native console ABI is added.
