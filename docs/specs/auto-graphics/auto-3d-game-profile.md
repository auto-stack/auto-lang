## Explicit staged scalar API

`profile() -> int` is2. `init()` establishes Auto state. `setup_camera(int,float)` installs16 immutable host projection components. A logical tick is `begin_tick(move_x,move_z,jump)`; any pending `random_request()` is answered by `random_value(sequence,float) -> accepted` using instance-owned seeded state. Accepted values stage until complete publication, and duplicate/wrong-order/stale-session responses are rejected. `move_chunk()` processes eight birth-ordered mob rows, then `finish_tick()` performs player integration and frozen collision/score/death semantics. These internal phases use the same retained Session CPU slices; only completed init/tick output is published.

Output roots: `object_count/object_alive/generation/identity/role/transform_field`, `status(score/dead)`, `event_count/event_field`. Slot0 has explicit player resource role0, game identity-1 and positive generation. Mob slots1..64 have explicit role1, monotonic spawn identity and increasing positive slot generation. Roles resolve only to the immutable, hashed original player/mob GLBs. Translation xyz, yaw/pitch/roll radians and positive scale xyz are nine f32 fields; the matrix is T*Ry*Rx*Rz*S. Auto has already evaluated local scene bob and pitch. Resource types/pointers/paths are not guessed or passed through the VM.

`Packet3d` carries session/sequence/profile, complete objects, score/dead and transient events. Event fields are[kind,game_identity,slot,score]; kind0=spawn,1=squash,2=screen-exit despawn,3=death. Death uses identity0/slot1 and current score as fixed non-object event fields. Spawn ordinals are monotonic; movement/despawn/collision preserve birth order through slot reuse. Squash adds exactly one score at most once per tick and destroys a known live mob. Death occurs once, hides the player and stops future spawning; existing mobs continue draining. A standalone `Publication3d` at producer and actual consumer rejects stale/mixed sessions/sequences/generations, unknown/duplicate events, nonfinite values, invalid scales/roles and disagreement between events and snapshot. Every consumer GPU resource is validated before CPU scene/HUD commit and frame work.
