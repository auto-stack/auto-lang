# Finite 2D editor viewport (PLAN-856)

The experimental Windows x64 single-window authoring host has one Editing-only `View2d`, separate from its Document, Auto VM and Play state. The supported child is 800×380 logical pixels. Its world center `c` is limited to ±65536 per axis and zoom `z` to [1/8, 8]; finite navigation saturates at these limits. The default is center (0,0), zoom 1, Grid off and Snap off, preserving the original scene view `(400+x, 190-y)`.

The shared mapping is `screen=(400,190)+z*(world.x-c.x, -(world.y-c.y))`. CompositionInput converts window physical coordinates to child logical coordinates once. Rendering centers and sizes, exact leaf picking, group bounds/origin, selection overlays, pointer capture and real Auto drag candidates consume the same presented view and revision. A changed view is not presented until a successful frame; stale/unpresented identities cannot start or publish a gesture. Logical screen widths and the 3px drag threshold are independent of zoom. Invalid or non-invertible input is rejected without changing the view or accepted Document. Projection overflow or draw capacity failure rejects the view update and preserves the last complete frame rather than admitting non-finite GPU data or silently truncating content.

In the 2D viewport, middle-drag pans by total displacement. Wheel zoom preserves the pointer's world anchor, with multiplier 1.1 per notch; winit physical pixel deltas are converted once to child logical units, with 40 logical pixels per notch and ±8 notches per event. F focuses the selected visible 2D leaf or visible group descendants with 80% fit; Home resets. These keys require the viewport keyboard target and no text focus. Selection that is empty, hidden, another dimension or beyond the supported center/zoom range reports a reason and leaves content unchanged. The panel supplies Grid, Snap, step, Focus and Reset controls.

Grid and axes are independent auxiliary drawing, aligned to world origin and rendered before scene content. Minor spacing follows 1/2/5 × 10^k with at least16 logical pixels; density coarsens before the 128-line limit. At most128 auxiliary rectangular commands and 16KiB CPU auxiliary array are admitted; the scene, selection and handles remain within the 4096-quad capacity. Grid off also disables these axes. Grid owns no scene nodes, VM or immutable mesh resources. Counters expose grid spacing/count and dynamic auxiliary cost separately from retained mesh uploads; no GPU timestamp or 60Hz claim follows.

Snap uses fixed world steps 1,5,10,50,100, default 10, independently of displayed grid spacing. For an object gesture, derive the final absolute world origin from its starting world origin and total child-pixel displacement, round each axis by `s*round_away_from_zero(x/s)`, and subtract the parent world translation to obtain the local result. Leaves/groups alter only their own local translation; 2D z remains zero. A no-op adds no history; an accepted drag adds one history step and supports Undo/Redo/save/reopen.

Navigation, object gestures, panel/text events and Play input are mutually separated. During an object candidate, view updates and settings are rejected; during navigation no object transaction starts. Esc cancels continuous navigation and restores the admitted starting view and 2D frame even when preparation rejects; blur, leave, resize/DPI and close end capture in the same way, and late move/up cannot publish. A completed wheel operation remains applied after later blur. New/Open success resets the view, failures preserve it; Save/Undo/Redo retain it. Run/Starting/Running/Paused/Faulted use the original runtime view with editor navigation disabled; Stop restores the retained editing view and content. View/grid/snap never enter scene4, dirty state or edit history.

## Finite 3D editor viewport (PLAN-857)

The experimental host additionally owns one Editing-only finite `View3d` per 3D viewport, separate from Document, Auto VM and Play state, reusing the 856 revision/cancel framework with separate dimension math; supported child is 800×400 logical pixels, right-hand Y-up. Target components are bounded to ±65536, distance to [0.5,4096], pitch to [-85°,85°] with finite normalized yaw and ortho height to [1/8,8192]; finite navigation saturates, and non-finite, zero-size or degenerate views are rejected keeping the previous view without touching Document validity. Explicit navigation uses perspective FOV60°, near 0.05, far 16384; the default and reset reuse the original sample_camera values including near/far and matrices, and old goldens are not regenerated.

RMB drag orbits the target, MMB pans the camera plane and the wheel dollys or ortho-zooms with the 856 notch conversion; F focus, Home reset and P projection toggle act only when the viewport holds keyboard target without text focus, with explicit panel controls. Perspective↔orthographic switching preserves target and direction and matches visible height `s=2·d·tan(FOV/2)` at the target plane, finite-saturating with a displayed limit when the required distance/height leaves range. Focus frames the selected model's mesh-union world bounds or the group's visible-descendant aggregate with a 20% screen margin under the actual aspect and projection; empty, hidden, cross-dimension or unframeable selection reports an observable reason and leaves content unchanged.

The XZ ground grid at y=0 is editing auxiliary, not a scene node: world origin and axes never move with the camera, generation stays within a bounded region of at most 4096 world units per axis, spacing selects from 1/2/5×10^k and coarsens whole-scale before the limits of 128 auxiliary lines (axes included) and 1024 submitted vertices. It draws under the same device, camera and depth rules as models through a bounded depth-assist pass with no depth write, no shadows and no scene nodes; real composites prove both visible lines and model-occluded lines, and forced depth Always, stale-camera picking and missing grid readback are permanent code mutations that fail the same gate and restore green. CPU auxiliary geometry stays ≤64KiB and attributable GPU auxiliary buffer+uniform ≤64KiB, metered per actual allocation separately from immutable mesh uploads; observed steady-state cost after 20 navigation/resize rounds remained within bounds (grid GPU 7232 bytes, CPU cache 8176 bytes) with no static mesh re-upload, no pipeline/target rebuild and only legal camera/grid dynamic uploads. Grid off draws and uploads nothing and default pixels equal the frozen 856 baseline. Close/resize/cancel cycles release the last owner; a bounded owner may be retained for reuse in closed scenes with weak-owner release.
