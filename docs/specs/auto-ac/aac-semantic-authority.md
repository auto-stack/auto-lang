# auto-ac: AAC 语义权威与受检 HIR

> **Status**: experimental（PLAN-1047 的 Windows x64 基础语义阶段）

## 运行边界

`experimental/ace/aac/semantics/` 消费 [AAC 源码前端](aac-source-frontend.md)
的严格 AST、源码范围和有序模块目录。`experimental/ace/aac/hir/` 负责本阶段
HIR 生成和复验。阶段载体由 Gen0 显式预建。载体处理用户源码时，名字绑定、类型求解、
声明规范化和 HIR 校验在 Auto 内执行。Rust 前端提供独立参考和下游安全复验。

## 绑定和类型事实

词法作用域、包和模块决定声明归属。公开别名和重导出保留真正定义身份。
调用依源码顺序求值，实参到形式槽位的映射另有独立表。全局初始化依已绑定
的读取与调用计算，循环有独立拒绝。原型归同模块唯一实际函数，原型注解填充
正文缺失的类型，受检 HIR 只发射该定义。

类型表显式区分基础数值宽度、Bool、文本、名义类型、函数、tuple、List、
Option、Result、Future 和 Iter。宽值检查、显式转换、构造载荷、解构字段及
绑定归属保留原范围。浮点字面量事实记录按目标宽度产生的位串。语义工作表
只在求解过程中使用。求解失败、无效源码、供应未决、资源拒绝与 OS 失败分别报告。

`aac.semantic-facts/1` 把已产出的绑定、类型、全局、声明标注和具名待办发布为
值快照。`SOURCE` 记录拼接源码的字节数和 BLAKE3，`MODULE` 记录逻辑名、
sourceId 及该范围。`DECL`、`USE`、`PROTOTYPE`、`ARG`、
`TYPE` 和 `TY` 的行号、映射及范围从同一份有序输入解释。原文变化触发
重新产出。声明标注保留 owner、名称和实参来源，实际消费者沿该身份读取。

## 外部供应和 HIR 权限

`FOREIGN-AUTHORITY` 只在已准入的 967 规范化页实际进入类型检查后出现。
Auto 对照签名、参数与返回类型、句柄来源、命名回调及已支持的 C 只读记录布局。
缺供应以及待编译期、实例或高级效果的工作有具名记录，整个候选暂停 Checked 发布。

已交 Checked HIR 阶段包含标量函数、局部读写、终结条件及早返回的后续块、
全局初值与访问、受检文本和借位以及可复制记录的构造与字段读取。
符号引用、owner、表达式图、调用映射、类型、初始化与借位由 verifier 从内容重验。
跨进程 Atom 或调用方的标志只传递候选，读回时再次经过同一验证，
涉及全局访问时同时比对原源码布局、初始化与访问签名。错误或未决保留已发布产物。

共享阶段规则见 [HIR 阶段合同](../auto-hir/stage-contract.md)。
