## 2. 应用独立化为何可以先行

用户已逐项确认仓名、产品合并、系统日志归属、Launcher 独立，以及建仓/接线的实际执行。
教学源码保留、四大主力 app 接入不改、应用 ID 与现有协议沿用，故无需等待新 HIR 或拆仓完成。
应用独立化是提前开发的一条已授权支线；未据此启动三仓搬迁或重构旧框架。

组合实现已在 AutoOS/v0.6-dev 发布并归档，21 个新产品仓、3 个已有应用仓固定提交可取回。
10-04 主检出递归初始化和源码核验通过，VM 桌面真实启动。功能扩展、完整后端/持久化、
双端回归和 Windows 插件 Launcher 仍待专项验收。

必须保留的合并风险：五个原 OS 实体目录（025/028/036/037/038）转 gitlink 后，
隐藏 v0.5 更新可能形成 modify/delete 或目录冲突。恢复时先保全完整源差异，
经各产品仓 source-sync 分支吸收，再更新 OS 的 gitlink；不得接受旧快照覆盖新源。
博客/视频/图片仓内 references 保留另一路原始来源，不宣称业务功能已经融合。
