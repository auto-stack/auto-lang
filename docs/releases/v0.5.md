## Auto Lang v0.5 发布说明

Auto Lang v0.5 将“脚本开发、转译发布”从语言工具链推进到跨端 UI、虚拟桌面与真实应用。
本说明覆盖 **v0.3（2026-04-12）至 2026-09-30 的已合入历史**，核查基线为 `14e444f02`，累计 **8,033 次提交**（包含功能、修复、文档与合并）。仓库尚无 v0.5 tag，因此这是滚动说明，不代表已冻结的发行包。v0.3 已有的泛型、所有权、AIE、Task/Msg 和多端 UI 原型作为基础，不重复计为本轮新创。

详细历史、提交锚点与限制见 仓库内 `docs/reports/v03-v05-history-audit.md`。

### 功能：从示例走向真实应用

- **AutoVM 与网络后端**：真正的多模块加载、跨模块全局状态、Actor 状态与协作调度、惰性生成器和流式 IO。`#[api]` 可运行 HTTP CRUD、路径参数与 JSON/SSE 服务；a2r 对应生成 Axum 后端。HTTPS、WebSocket、上传与断点下载逐步补齐。9 月引入按名参数绑定，并以 Axum/Hyper 替换 VM HTTP 服务的手写传输解析器。
- **Rust 互操作与 a2r**：内建 native 与 `dep` / `use.rs` 构建期 shim 支撑 Rust 调用；rustdoc 签名、同编译实例布局探针和缓存制备绑定，新增字段、Option/Result、具体泛型实例与 trait 相关能力。a2r 增强多文件转译、所有权映射、外来泛型/trait/dyn 类型、线程透传及 C ABI 双向互操作；SQLite、Redis 运行时与真实库语料补齐。能力以具体签名和验证语料为准，不承诺任意 Rust 库、生命周期敏感接口或 unsafe 代码均可直接调用。
- **Python 与脚本模式**：AutoVM 嵌入 CPython，支持 `use.py`；a2py 输出 Python。新增 `.as`（或 `#[script]`）模式，经源码 lowering 提供方法/切片糖、真值判断、`with … as`、kwargs、异常传播和外对象分发；`null` 错用从静默错误改为可捕获诊断。PyTorch 推理、训练与自定义 Module/Dataset 回调已有三方对拍语料，尚不能等同全部 Python 语言或库兼容。
- **多目标生态**：Rust 为主要静态发布路径；C、TypeScript、Python、GDScript 与 Godot 场景生成各有独立测试面，r2a 提供 Rust → Auto 逆转译。ArkTS 与 Jetpack Compose 有生成器及可行性 Demo；完整移动端与 MCU 产品路线仍需后续建设。
- **AutoUI**：同一份 `.at` 声明状态、事件和视图，支持 Vue/Web 与 iced/Desktop。组件生命周期、子组件状态、API 前后端调用、主题 token、菜单族、编辑器、图表、图片及真实音视频服务持续完善；桌面支持热重载与 F12 DevTools。Vue、VM 与 a2r 各有验证面和已知差异，不将局部对拍结果扩写为全部组件全等。
- **AutoOS 与应用生态**：单宿主窗口虚拟桌面、WM-as-App、启动器、任务栏、深浅主题、设置与桌面应用集逐步落地。应用轨资产迁至 `auto-os`，语言仓保留示例轨和框架；系统应用成熟度各异。AutoShell 核心为 Rust，Auto 为内置脚本及 GUI 语言；AutoMusk 后端为 Rust、前端视图由 Auto 生成；AutoDown/Jade Garden 展示前后端 Auto 单源；AutoEdit 是编辑器应用探索。这些兄弟项目作为集成成果介绍，其全部提交不计入本仓统计。

### 架构：单源、多运行路径与可验证的自举

- **值与 VM 内核**：NanoValue 单槽表示、池引用计数与长期 churn 防线持续加固；模块编译/链接、初始化与外对象调用路径完善。9 月 UI handler 的 park/resume 段执行取代 UI 路径忙等，降低等待对交互的阻塞。
- **AURA 契约**：`schema/aura.at` 驱动注册表和多端映射，UI 方言仍产出基础 AST；生成器、VM 渲染和后端装配分层。Blueprint（原 Blocks）与 stylekit 提供可复用规格、组件及样式配方。
- **桌面进程与渲染协议**：从单进程虚拟窗口扩展至 broker、RenderQueue、原生应用进程和 desktop endpoint；9 月退役旧 AppProjector 路径并统一 RqProjector。remote 路径新增 headless display-list 重放、输入/IME 回传与试点验证，这是跨进程渲染能力，不等同已交付互联网远程桌面产品。
- **编辑器底座**：共享 code_editor 内核引入 AVL rope、COW 快照、统一编辑 delta 和结构化编辑接口，新增文本/目录 diff 引擎。全文物化等路径仍限制大文件交互性能，不据此宣称大文件编辑已全面优化。
- **自举² 已达成验证目标**：Auto 编写的 aavm 与 aa2r 从早期 lexer/parser、简单程序推进至编译包含自身的库。GOAL-017 的双运行目标、塔顶语义差分、原生二代一致性和 AA2R 自译均有收据。这是“曲线自举”：Auto → Rust → Rust 编译器 → 原生二进制，尚非直接发射机器码；宿主 Rust 实现仍为参考，自举实现仍属实验工具链，未覆盖全部宿主语言能力。
- **LAOS 与前后解耦**：UI/渲染器、应用/桌面宿主和 AutoAI Client/Daemon 展示这一方向。Linux 发行版、OpenHarmony 内核路线、MCU RTOS 与完整 LLM Key Vault/预算调度属于后续设计，不列为本次已交付能力。

### 开发者体验：更易调试、复现和验收

- **界面可观测**：MCP 提供实时 VTree、布局、事件操作和截图；Select Anything 增加框选并导出 Auto/JSON/Atom 的结构化采集通道，支持 Agent 检查实际界面与源码映射。
- **Playground 与文档**：运行、调试回放、源码/转译结果关联及示例/书页语料集成持续完善；LSP、结构化诊断和文档站共同支撑开发。在线样本数量属于内容快照，并非兼容率指标。
- **缓存与启动体验**：AutoCache 管理构建指纹及 shim；UI 生成器指纹纳入缓存键，生成器升级自动失效旧产物；画廊增量扫描缓存减少重复工作。
- **Parity 与回归**：AutoVM/a2r/原生 Rust、AutoVM/a2py/原生 Python 和自举多路径对拍检查行为。除 20+ 库复刻语料外，增加真实 crates.io 依赖、字段/布局/泛型与 PyTorch 回调测试。结果绑定套件及环境，仍保留已知分歧。
- **工程纪律**：Plan/Spec 账本、修订绑定复审、独立 worktree、资源分组与分层测试落地。日常档与 VM/转译/UI/自举专项分开，重型批量回归单实例运行，减少资源互扰。

### 已知边界与 v0.6 展望

各路径成熟度不同，当前仍有 UI 布局/命中及媒体交互修复、跨端语义差异、Rust 桥签名限制和编辑器性能债。已合入修复不等于全部验收通过；在途工作以 Plan 与已知债登记为准。

v0.6 继续完善语言/标准库、Rust/Python 互操作、AutoUI 双端一致性及 DevTools/MCP，提升 AutoMusk、AutoShell 与桌面应用的日常可用性。自举下一步是维护、扩展既有闭环，原说明中“v0.6 才实现 VM 自举、转译器留待 v0.7”已过时。

Linux/COSMIC 发行版、跨平台桌面与 AutoWeb 远程桌面、鸿蒙/Android/iOS、ROS2/DORA、Godot 和 MCU 生态仍是路线图方向；本说明不承诺发布日期或全部完成范围。
