## v0.6的几大任务

v0.6是Auto语言生态基础框架搭起来之后的第一次大重构，
主要做以下4个路线的任务：


1. 项目拆分与重构
2. 新版ACE编译执行引擎
3. 新版AGE统一图形引擎
4. Linux发行版

## 1. 项目拆分与重构

v0.5版之前用AI做了100w行的Rust代码和40w行的Auto代码，
主要任务是添加新能力，完成整体生态的架构，
整个过程是基本连续的，并没有停顿下来对整体架构和代码逻辑进行大型的重构。

因此v0.6开始之前的第一件大事就是重新分析当前的实现，
找到可以拆分重构的地方，进行大规模的重构。

这个过程花了近3周时间，花了100多个计划，几乎把整套代码都重新整理了一遍。

总体效果：

1. 70w行的auto-lang大项目被拆分成了三个大的仓库，十多个crate。
2. auto-lang， auto-ui和auto-man三个大工程解耦合。
3. 编译速度和测试速度都得到了很大的提升，整个工程的架构也更加清晰了。
4. 重构了整个生态的测试框架。
3. 在重构调研的过程中发现现版AutoVM/A2R引擎很多架构上可以改良的地方。
4. 重构过程中发现AutoUI可以和未来的2D/3D图形引擎可以融合到一起.

## 2. ACE编译执行引擎

这个引擎最开始只打算调研Auto语言自身的代码生成能力，
即不借助Rust，直接生成二进制文件的CodeGen后端。

在设计和开发的过程中，结合对现版AutoVM/A2R引擎的重构分析，
我们打算把ACE引擎做成通用的架构：同一套Auto语言，在ACE中可以实现：

- 编译期执行（CTE），
- 脚本执行（AV）
- 二进制执行（AVB）
- JIT编译（AJ）
- 转译（A2X）
- AOT编译（AC）

且上述所有模式会自动切换，并以最精确的粒度（函数/Symbol/Section级别）实现增量编译和热重载能力。

ACE的这套架构相当于更加统一的V8引擎+WASM+LLVM，
把Auto语言从脚本语言+插件式语言+系统语言的多个方面融合到一个自动的编译流程中。

因此我认为，ACE引擎是真正让Auto语言成为六边形战士的基础。

先阶段ACE的M1已经基本完成，有如下模块：

| crate | 行数 | 文件数 |
| --- | --- | --- |
| av（AV 虚拟机） | 83,533 | 145 |
| core | 72,576 | 72 |
| native（原生后端） | 40,796 | 87 |
| abi | 38,324 | 50 |
| av-core（VM 核心指令） | 33,912 | 27 |
| source-query | 17,070 | 33 |
| a2x-worker | 15,844 | 53 |
| comptime | 10,338 | 20 |
| 其余 22 个 crate | 各 < 1 万 | — |

M1的主要任务是调研，只实现了Auto语言的一部分语言特性（基本数值计算，函数，控制流，简单类型，闭包等）

但从架构上已经很完善了：

我们设计了Auto独有的HIR，并用Atom作为HIR的表达和Schema的定制语言，让它可以实现多种方言。
我们设计了Auto通用的ABI，并为它提供了C和Rust的ABI的适配器，并实现了新版的FFI。
ACE的FFI基本能做到对各种其他语言都兼容，且性能基本做到最优，且对C/Rust均实现了热重载。
我们设计了新版的ABC二进制语言，不再只是解释器的附属，而是像WASM那样可以成为通用的插件式执行环境。

ACE的M2的主要任务是扩展语言支持，做到支持完整的Auto；然后替换现有的AutoVM和A2R.
这部分工作将在接下来的一两周实现。

## 3. AGE引擎

由于元宇宙是Auto语言的长期支持生态，我们开始对2D/3D引擎进行调研和支持。

经过和AI的反复讨论和论证，我们从最初的“嵌入到Godot引擎”的方案，改成了用Auto来声明，适配多个图形后端的方案。也就是Auto Graphics Engine (AGE)。

初版调研我们采取的后端是wgpu。后考虑到我们的AutoUI的后端（iced）的底层其实也是wgpu，
因此我们打算把AutoUI也融合到AGE引擎中统一实现。

经过重新设计，AGE可以用同一套语法，支持任意UI应用，内嵌2D/3D的游戏画布，而画布游戏之内，又可以内嵌AutoUI的界面。这样做到了UI/2D/3D图形的任意组合嵌套。

从架构上讲，AGE将会使一套全新的通用图形引擎，它会比现在的WEB技术：

前端HTML/JS/CSS + 画布Canvas + WebGPU

拥有更加统一的语法，更加一致的运行环境，理论上也有更高的性能上限。

因此，AGE有希望成为下一代互联网和元宇宙的基础设施。

未来等AGE完善并合并回AutoUI之后，我们规划在AGE的基础上做出下一代的浏览器：AutoScape。


AGE引擎分为3个里程碑：

- M1: 调研性的2D和3D引擎，把整个AGE架构搭起来。
- M2: 进一步强化2D和3D引擎，完成可玩的示例游戏。并等待ACE的M2
- M3: 基于ACE，用AGE替换现有的AutoUI（包括现有的桌面和应用）

现在M1已经基本完成；AGE已经有了几个Demo小游戏。
M2已经开始初步调研。

## 4. Linux发行版

我们的Linux发行版名称叫 Aunix， 它的设计目标是下面3套体系的融合与创新：

1. Pop!OS+Cosmic Desktop，这是一套Rust/iced的发行版，我们主要参考它的Rust实现。
2. NixOS：配置型OS。我们打算基于它的配置系统，改用Auto语言作为配置语言。
3. Omarchy：我们参考它的Tile组合式桌面，可定制多主题桌面，以及install体系

现在这个路线正在开发中，3个方向各自进度如下：

1. 基于NixOS+Cosmic自己定制的发行版已经基本可用（生成了ISO，安装后可以用）
2. 对Cosmic的应用的逐个替换，正在试验和进行中。替换的对象是我们AutoOS的对应的应用，如
auto-edit替换cosmic-edit。
3. 完善AutoOS的应用（之前大部分是UI Demo，实际功能并不可用），已经完成了一大轮改进，现在28个应用基本都可以用了。

预计下周末可以完成应用替换，并做出一个基本能用的发行版ISO。
