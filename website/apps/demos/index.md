# System applications and demos

System applications and demos introduce everyday tools and interactions in the Auto ecosystem, from tasks, calendars, and media to file management, launchers, and games. Features and readiness vary: some are integrated desktop applications, while others primarily illustrate interface and application structure.

[Application overview](/apps) · [AutoOS virtual desktop](/autoos/) · [AutoUI](/ui)

## Explore by purpose

| Category | Examples to start with | What they introduce |
|---|---|---|
| Work and daily life | Calculator, clock, tasks, calendar, notes, weather | Input, filtering, date selection, and everyday information |
| Reading and communication | Book reader, blog reader, chat | Content browsing, messages, and reading layouts |
| Media and creation | Music, video, photos, image viewer, painting | Media controls, file resources, and creative interaction |
| System and data | File manager, launcher, monitor, logs, terminal, settings, database | Desktop entry points, system information, and data tools |
| Games | Tetris, Solitaire, Minesweeper | Keyboard and pointer interaction, game state, and multiple windows |
| Application structure | Kanban, RealWorld, charts | Task flows, routing, frontend/backend structure, and data presentation |

These categories help explain applications. They do not establish equal product readiness or browser availability. Development examples, desktop integration, and desktop icons cover different sets; one fixed count cannot describe all of them.

## Ways to explore

### Introductions and real captures

Explain an application's purpose and one or two typical operations, then show real interface captures. Visitors can understand an application even when it needs local files, a database, or system services. Captures and runtime requirements will be added individually.

The [virtual desktop workspace captures](/autoos/#desktop-showcase) already show the launcher, games side by side, and an editor alongside tasks and a calendar. They record the actual captured interface, rather than verifying every application feature.

### Development example gallery

The [existing application gallery (shared entry)](/ui/demos/) offers interfaces, sources, and development material. Some examples need a backend, host capabilities, or external resources. Mounting an interface does not establish that all operations work in a static deployment.

This introduction helps people choose and understand applications; the gallery helps study their interfaces and implementation. It has a separate entry point and is not automatically embedded here.

### Online trials and local use

Only applications verified in a deployment without a backend should receive individual online-trial links. Operations needing file access, terminals, real monitoring, databases, or model services should explain local prerequisites.

A small number of service-dependent examples may justify a separate fixture-based demonstration. It must explain data sources, resetting, and persistence. Demonstration behavior and real service capabilities should be described separately.

## Applications, examples, and components

The [four main applications](/apps#main-apps) have their own product introductions. System apps and demos explain desktop use and application development. Buttons, tables, dialogs, and other components are covered in the [UI component gallery (shared entry)](/ui/gallery/index.html).
